## 공통 규약 (모든 프롬프트 앞에 한 번만 선언)

새 세션을 시작할 때마다 아래 블록을 먼저 붙여넣는다.

> 너는 '피지컬브레인(Physical Brain)' 앱의 개발 파트너다. 프로젝트 공통 규약:
> ① 저장소 이름 `physical-brain`, 모노레포 구조: `/server`(FastAPI 백엔드), `/web`(대시보드), `/graph`(온톨로지·Cypher), `/pipelines`(데이터 수집), `/robot`(어댑터, 2차), `/docker`(compose 파일), `/docs`, `/tests`.
> ② 언어·스택: Python 3.11+, FastAPI, Neo4j 5(도커), APScheduler(스케줄), SQLite(경량 상태), 프런트는 서버렌더(FastAPI+Jinja2+HTMX) 우선 — 1차에서는 React 금지(단순 유지).
> ③ 원칙: 로컬 퍼스트(외부 API로 건강 데이터 전송 금지), 모든 설정은 `.env`, 모든 기능은 pytest 테스트 동반, 커밋 메시지는 한국어.
> ④ AI 사서의 4대 금지(진단·처방·응급판단·불안조장)를 시스템 프롬프트 상수로 관리한다.
> ⑤ 완료 시 항상: 실행 방법(README 갱신) + 테스트 통과 로그를 보여줄 것.

# Phase 0 · 개발 환경과 뼈대 (오늘, 이 컴퓨터) — T01~T03

### T01. 저장소·프로젝트 뼈대 생성 | 산출물: 실행되는 빈 앱 | 완료: `make dev`로 헬스체크 응답
[선행: 없음]

> 위 공통 규약대로 `physical-brain` 모노레포를 생성해줘. FastAPI 앱을 `/server`에 만들고 `GET /health`가 `{"status":"ok","version":"0.1.0"}`을 반환하게 해. `docker-compose.yml`에 neo4j:5 서비스(계정은 .env)를 포함하고, `Makefile`에 dev(로컬 실행)/up(도커)/test(pytest) 타깃을 만들어. `.gitignore`, `README.md`(설치·실행법), pre-commit(black+ruff)까지. 마지막에 서버를 실행해 /health 응답을 보여줘.

### T02. 온톨로지 v1 스키마 코드화 | 산출물: 스키마 정의 + 생성 스크립트 | 완료: Neo4j에 제약조건·인덱스 생성 확인
[선행: T01]

> `/graph/schema.py`에 서드브레인 표준 개인 온톨로지 v1을 코드로 정의해줘. 노드 7종: Person, Medication, Regimen, Measurement, Activity, Event, Place. 관계 6종: TAKES(사람→약), HAS_RULE(약→복약규칙), MEASURED(사람→측정값), PERFORMED(사람→활동), OCCURRED(사람→이벤트), RELATES_TO(임의↔임의). 각 노드의 필수/선택 속성을 dataclass로 명세하고(예: Regimen{time,condition,caution}, Measurement{type,value,unit,measured_at}, Place{name,x,y,theta}), `/graph/init_db.py` 실행 시 Neo4j에 유니크 제약조건과 인덱스를 생성하게 해. 스키마 문서를 `/docs/ontology-v1.md`로 자동 생성하는 스크립트도 추가. pytest로 스키마 왕복(생성→조회) 테스트.

### T03. 샘플 볼트와 시드 데이터 | 산출물: 옵시디언 호환 샘플 노트 12개 + 시더 | 완료: 그래프에 사람2·약3·규칙3·장소4 적재
[선행: T02]

> `/graph/sample_vault/`에 옵시디언 호환 마크다운 노트 12개를 만들어줘. 프런트매터 규약: `type: medication|person|place`, 약 노트는 `for: "[[아버지]]"`, `treats`, `rule_time`, `rule_condition`, `rule_caution` 속성. 구성: 사람 2(나, 아버지), 약 3(혈압약-아버지, 오메가3-나, 전립선약-아버지), 장소 4(부엌약선반, 식탁, 소파, 홈스테이션 — 좌표 속성 포함). `/graph/seed.py`가 이 볼트를 파싱해 T02 스키마대로 Neo4j에 적재하게 하고, 적재 결과 요약(노드/엣지 수)을 출력해.

# Phase 1 · 데이터 파이프라인 (이 컴퓨터) — T04~T08

### T04. 볼트→그래프 동기화 엔진 | 산출물: 증분 임포터 | 완료: 노트 수정 후 재실행 시 그래프 갱신
[선행: T03]

> `/pipelines/vault_sync.py`를 만들어줘. 지정 폴더의 마크다운을 스캔해 프런트매터 `type:`이 있는 노트만 노드로 변환, `[[위키링크]]`와 속성을 엣지로 변환해 Neo4j에 MERGE(멱등)한다. 삭제된 노트는 그래프에서 `archived=true` 마킹(물리 삭제 금지 — 원칙: 진실의 원본은 볼트). 해시 기반 증분 처리로 변경 노트만 갱신. CLI: `python -m pipelines.vault_sync --vault ./graph/sample_vault --watch`(watchdog로 실시간 감시 모드). 테스트: 노트 수정→동기화→그래프 반영 확인.

### T05. 건강 데이터 목업 생성기 | 산출물: 현실적 가짜 6신호 생성기 | 완료: 30일치 데이터가 그래프에 적재
[선행: T02]

> 실기기 연동 전 개발용으로 `/pipelines/mock_health.py`를 만들어줘. 사람별로 30일치 현실적 데이터 생성: 혈압(아침·저녁 2회, 아버지는 평균 138/88에 요일 변동, 나는 122/78), 심박 RHR(개인 기준선±5, 음주 가정일 +8), HRV(주중 하락 추세 패턴), 혈당 CGM(5분 간격, 식후 스파이크 — 면 요리 가정일 급등), 수면(시간+취침시각 일관성, 목요일 무너짐), 걸음수. 결측 원칙: 전체의 10%는 '결측'으로 남길 것(0으로 채우기 금지). Measurement/Activity 노드로 그래프 적재 + 시각화 확인용 `GET /api/mock/summary` 엔드포인트.

### T06. 헬스 커넥트/CSV 인제스트 | 산출물: 실데이터 수입 경로 | 완료: 삼성헬스 내보내기 CSV가 그래프로
[선행: T05]

> `/pipelines/ingest.py`를 만들어줘. 1차 구현은 파일 기반: 삼성헬스/애플건강의 내보내기 CSV·JSON을 파싱해 Measurement/Activity 노드로 정규화 적재(중복 방지: 소스+타임스탬프 해시 키). 지원 신호: 심박, 걸음, 수면, 혈압(수동 CSV), 혈당 CSV. 폴더 감시 모드: `~/physical-brain/inbox/`에 파일이 떨어지면 자동 처리 후 `processed/`로 이동. 스키마가 다른 파일은 `failed/`로 옮기고 이유를 로그. 샘플 CSV 3종을 `/tests/fixtures`에 포함해 테스트.

### T07. 오늘의 작업 목록 생성기 | 산출물: 복약 스케줄 전개 엔진 | 완료: 매일 0시 오늘 할 일이 생성됨
[선행: T03]

> `/server/tasks_today.py`를 만들어줘. 매일 00:05(APScheduler)에 그래프의 Regimen을 읽어 오늘 날짜의 TaskInstance(SQLite)로 전개한다: {누가, 약, 시각, 조건, 주의, 상태=pending}. 상태 전이: pending→announced→confirmed|missed|unconfirmed. API: `GET /api/tasks/today`, `POST /api/tasks/{id}/confirm`(음성/버튼 확인 대체). 규칙이 볼트에서 바뀌면 다음 날 자동 반영됨을 테스트로 증명(볼트 수정→sync→재전개).

### T08. 이벤트 기록기와 감사 로그 | 산출물: 모든 행동의 그래프 기록 | 완료: 복약확인이 Event 노드로 남음
[선행: T07]

> `/server/events.py`를 만들어줘. 시스템의 모든 유의미한 사건(복약 확인/미확인, 알림 발송, 임계 초과, 데이터 결측 감지)을 Event 노드로 그래프에 기록하는 단일 함수 `record_event(person, kind, payload)`를 만들고 전 모듈이 이것만 쓰게 해. '미확인은 미확인으로 기록' 원칙: 20분 무응답 시 1회 재알림 후 unconfirmed 이벤트 생성. `GET /api/events?days=7` 조회 API와 주간 복약 준수율 계산 함수(confirmed/(confirmed+missed+unconfirmed)) 포함.

# Phase 2 · AI 사서 (이 컴퓨터, 경량 모델) — T09~T12

### T09. 로컬 LLM 연결 계층 | 산출물: LLM 추상화 + Ollama 연동 | 완료: 경량 모델로 한국어 응답
[선행: T01]

> `/server/llm.py`를 만들어줘. Ollama HTTP API 래퍼로 `chat(system, messages, json_mode=False)` 단일 인터페이스를 만들고, 모델명은 .env(`LLM_MODEL`, 기본은 이 컴퓨터에서 도는 경량 한국어 가능 모델로 설정하되 주석으로 '2차 GPU 서버에서 대형 모델로 교체 — URL만 변경' 명시). 4대 금지 시스템 프롬프트 상수 `LIBRARIAN_SYSTEM`을 여기 정의: 진단·처방·응급판단·불안조장 금지, 상관≠인과, 격려 어조, 근거 없는 수치 생성 금지. 재시도·타임아웃·오프라인 폴백(LLM 불가 시 규칙 기반 문장 생성) 포함. 모킹 테스트.

### T10. 그래프 RAG 사서 | 산출물: 자연어 질문→그래프 조회→근거 답변 | 완료: "이번 주 아침 혈압 추세는?" 정답
[선행: T05, T09]

> `/server/librarian.py`를 만들어줘. 파이프라인: ①사용자 질문 → LLM이 '의도+파라미터' JSON 추출(예: {intent:"bp_trend", person:"아버지", days:7}) ②의도별 **사전 정의된 Cypher 템플릿**(자유 Cypher 생성 금지 — 안전) 실행 ③결과 rows만 컨텍스트로 LLM이 요약 답변. 의도 8종 우선 구현: 혈압추세/복약준수율/오늘약/결측조회/수면요약/혈당스파이크/HRV비교/이벤트조회. 답변엔 반드시 수치의 출처 기간 명시. API `POST /api/ask {question}`. 테스트: 목업 데이터 기준 정답 검증 5케이스 + 금지영역 질문("무슨 병이야?")에 병원 안내로 응답하는지.

### T11. 이중 안전망 규칙엔진 | 산출물: 1층 임계값 감시 | 완료: 목업 고혈압 데이터에 즉시 알림
[선행: T05, T08]

> `/server/safety.py`를 만들어줘. 1층(규칙): 새 Measurement 적재 시 임계값 검사 — 기본표(수축기≥180 또는 이완기≥120: 긴급 / ≥135·85: 주의 / CGM 급등 기울기)와 개인별 오버라이드(.yaml). 긴급은 **고정 문구**("병원 안내" 문구 상수 — LLM 개입 금지)로 즉시 이벤트+알림. 2층(AI): 일 1회 배치로 7일 추세를 사서에게 요약시켜 '관찰' 등급 알림 생성(제안 어조). 알림은 T13 발송기로 위임. 테스트: 임계 케이스 표 기반 파라미터라이즈드 테스트.

### T12. 아침 브리핑 생성기 | 산출물: 매일 아침 브리핑 텍스트 | 완료: 07:00 브리핑이 생성·기록됨
[선행: T07, T10, T11]

> `/server/briefing.py`를 만들어줘. 매일 07:00에 조립: ①어젯밤 수면 ②오늘 RHR(기준선 대비) ③아침 혈압(있으면) ④오늘의 복약 목록(T07) ⑤안전망 알림(있으면) ⑥AI 한 줄 관찰(2층 어조). 사서를 통해 자연스러운 한국어 문단으로 합성하되 모든 수치는 그래프 조회값만 사용. 산출물은 briefing Event로 기록 + `GET /api/briefing/today`. 사람별 개별 브리핑(나/아버지) 지원.

# Phase 3 · 오케스트레이터와 시나리오 (이 컴퓨터) — T13~T16

### T13. 알림 발송기(텔레그램) | 산출물: 대외 채널 1종 | 완료: 폰으로 브리핑 수신
[선행: T12]

> `/server/notify.py`를 만들어줘. 텔레그램 봇 API로 사람별 chat_id에 발송(.env 토큰). 발송 유형: briefing/reminder/alert/report. 원격 케어용 '보호자 알림' 라우팅: 아버지의 복약 confirmed/unconfirmed 이벤트를 아들 chat_id로 전달("아버지 복약 완료 07:31 ✓"). 봇 수신 명령 2개: `/오늘`(오늘 작업 목록), `먹었어`(가장 최근 announced 태스크 confirm — T07 API 호출). 발송 실패 재시도 큐 포함.

### T14. 오케스트레이터 코어 | 산출물: 조건-확인-행동 규칙엔진 | 완료: YAML 규칙으로 시나리오 구동
[선행: T08, T13]

> `/server/orchestrator.py`를 만들어줘. 규칙 문형: "[조건]이 되면 [확인]하고 [행동]을 발행한다"를 YAML로 선언(`/server/rules/*.yaml`). 조건 타입: 시각(cron), 이벤트 발생(kind 매칭), 측정값 조건. 확인 타입: 그래프 질의 결과 검사. 행동 타입: say(1차에선 notify로 대체), move/manipulate(1차에선 로그만 남기는 **시뮬레이션 스텁** — 2차 로봇 어댑터가 같은 인터페이스 구현), record(이벤트 기록). 규칙 실행 이력을 전부 이벤트로. 예제 규칙 3개 포함 배포.

### T15. 시나리오 A·B·C 구현(시뮬레이션 모드) | 산출물: 규칙 3세트 | 완료: 하루 가속 시뮬레이션 통과
[선행: T14]

> `/server/rules/`에 시나리오 3종을 YAML로 구현해줘. A(아침 복약): 07:00+기상이벤트 → 오늘 아침 규칙 조회 → 알림·(스텁)서빙 → 확인 루프(20분 재알림→unconfirmed). B(혈당): CGM 급등 이벤트 → 최근 식사 확인 → 산책 권유 알림 **1회만**(쿨다운 4시간). C(저녁): 21:30 → 하루 요약 브리핑 + (스텁)내일 트레이 준비 + 하루 마감 이벤트. 그리고 `/tests/test_scenarios.py`에 **가상 시계로 하루를 10초에 돌리는 시뮬레이터**를 만들어 세 시나리오의 전 상태 전이를 검증해줘.

### T16. 주간 리포트 | 산출물: 주간 요약 발송 | 완료: 일요일 리포트 수신
[선행: T13, T15]

> `/server/report.py`를 만들어줘. 매주 일요일 20:00, 사람별 주간 리포트 생성: 복약 준수율(그래프 계산), 혈압 주간 평균±전주 대비, 수면 규칙성, 걷기 누적, 이벤트 하이라이트, 사서의 3줄 관찰. 텔레그램 발송 + Event 기록. 보호자 공유 버전(아버지 리포트→아들)에는 "전화할 거리" 한 줄 제안 포함(예: "이번 주 걷기 목표를 채우셨어요 — 칭찬 전화 어떠세요?").

# Phase 4 · 앱 대시보드 (이 컴퓨터) — T17~T20

### T17. 웹 대시보드 뼈대 | 산출물: 6신호 대시보드 | 완료: 브라우저에서 30일 추이 확인

### T18. 그래프 뷰어 | 산출물: 온톨로지 시각화 | 완료: 내 그래프를 브라우저에서 탐색

# Phase 5 · 2차: GPU 서버 (T21~T25)

### T21. GPU 서버 환경 구축 | 산출물: CUDA 도커 호스트 | 완료: nvidia-smi + 도커 GPU 컨테이너 구동
[선행: T20 / GPU 서버 확보]

> GPU 서버(우분투 가정)를 셋업하는 스크립트와 문서를 만들어줘: NVIDIA 드라이버·CUDA·docker·nvidia-container-toolkit 설치 확인 스크립트, 방화벽(로컬 네트워크만 개방 — 외부 포트 금지, 접근은 테일스케일 VPN 권장), `physical-brain` 저장소 배포 방법(도커 컴포즈 프로파일 `gpu`). 헬스체크: GPU 컨테이너에서 torch.cuda 확인.

### T22. 대형 LLM 서빙 승격 | 산출물: 원격 사서 | 완료: 대시보드 질문이 GPU 모델로 응답
[선행: T21]

> GPU 서버에 대형 한국어 LLM 서빙을 올려줘(Ollama 또는 vLLM, .env로 선택). 로컬 앱은 `LLM_BASE_URL`만 GPU 서버 주소로 바꾸면 되도록 T09 추상화를 검증·보완. 응답 품질 비교 스크립트: 동일 질문 10개를 경량/대형 모델에 보내 답변을 나란히 저장(`/docs/llm-comparison.md`). 건강 데이터가 GPU 서버 밖으로 안 나가는지(외부 egress 없음) 확인 항목 포함.

### T23. 음성 계층(STT/TTS) 서버 | 산출물: 한국어 음성 API | 완료: 음성 질문→사서→음성 답변 왕복
[선행: T22]

> GPU 서버에 STT(faster-whisper)와 한국어 TTS 서비스를 도커로 올리고 `/robot/voice_client.py`를 만들어줘: 마이크 녹음→STT→사서(T10)→TTS→스피커 재생의 왕복 데모(노트북 마이크로 시연 가능). 웨이크워드는 2차 범위 외로 표시하고 푸시투토크로 구현. 지연 측정 로그(STT/LLM/TTS 각 구간) 포함.

### T24. LeRobot 학습 파이프라인 | 산출물: 모방학습 훈련 환경 | 완료: 공개 샘플 데이터셋으로 훈련 1회 완주
[선행: T21]

> GPU 서버에 LeRobot 학습 환경을 구축해줘: 저장소 클론·의존성 도커화, 공개 샘플 데이터셋으로 정책 훈련을 끝까지 1회 실행하고 체크포인트·로스 곡선을 저장. 우리 데이터셋 형식 문서(`/docs/dataset-spec.md`): SO-101 시연 녹화가 도착하면 어떤 폴더 구조·명령으로 훈련하는지 런북 작성. (실물 팔 도착 전이므로 '데이터만 오면 돌아가는 상태'가 목표.)

### T25. 로봇 어댑터 명세와 MQTT 브리지 | 산출물: 명령3/보고3 인터페이스 구현 | 완료: 가상 로봇이 시나리오 A 완주
[선행: T14, T21]

> `/robot/adapter.py`와 MQTT 브리지를 구현해줘. 토픽 명세: `pb/cmd/move {place_id}`, `pb/cmd/manipulate {skill}`, `pb/cmd/say {text}` / `pb/report/result {ok,reason}`, `pb/report/state {pose,battery}`, `pb/report/event {kind,payload}`. T14 오케스트레이터의 스텁을 이 브리지로 교체하는 어댑터 패턴 적용. 그리고 `/robot/fake_robot.py`: 이동 3초·조작 2초 걸리는 **가상 로봇**을 만들어 시나리오 A가 가상 로봇으로 전 구간(이동→집기→서빙→확인) 완주되는 통합 테스트를 작성해줘. 이것이 실물 LeKiwi/휴머노이드 접속 전의 최종 리허설이다. 인터페이스 명세서를 `/docs/robot-adapter-v1.md`로 고정(이후 변경은 버전업으로만).

## 마일스톤 재정의 (앱 개발 기준)

| 마일스톤 | 내용 | 해당 태스크 |
| --- | --- | --- |
| M1 | 그래프가 살아있다 — 볼트·목업 데이터가 그래프로 흐름 | T01~T08 |
| M2 | 사서가 답한다 — 그래프 RAG + 안전망 + 아침 브리핑 | T09~T12 |
| M3 | 하루가 자동으로 돈다 — 시나리오 A·B·C 시뮬레이션 완주 | T13~T16 |
| M4 | 눈으로 본다 — 대시보드·그래프 뷰어·데모(1차 완성) | T17~T20 |
| M5 | GPU로 승격 — 대형 LLM·음성·학습·가상 로봇(2차 완성) | T21~T25 |

## 진행 요령 5가지

1. **한 세션 = 한 태스크**: 공통 규약 + 해당 프롬프트만 붙여넣고, 완료 기준을 확인한 뒤 커밋하고 다음으로.
2. **막히면 완료 기준을 다시 읽기**: 프롬프트보다 완료 기준이 우선이다. AI에게 "완료 기준 ○○를 통과하도록 수정해줘"라고 요구할 것.
3. **T05(목업)를 아끼지 말 것**: 실기기 연동 전 모든 개발이 목업 위에서 돈다. 현실적일수록 뒤가 편하다.
4. **매 태스크 끝에 `make test`**: 통과 로그 없이 다음 태스크로 넘어가지 않는다.
5. **2차 이관의 열쇠는 .env**: 1차 내내 "URL만 바꾸면 GPU로 간다"를 지키면 T21~T22는 반나절 거리다.
