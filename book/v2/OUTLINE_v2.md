## 관통 철학 (프롤로그에서 선언, 1부 전체가 실행)

```
[한 세대 전 현장]                  [지능형 AI ERP 플랫폼]
3정5S (정위치·정품·정량)     →    데이터의 3정5S (마스터 정비·정합성·정확한 수량)
눈으로 보는 관리 (관리판)     →    데이터로 보는 관리 (실시간 수집·가시화)
개선의 QC 스토리             →    6시그마 DMAIC 사이클
사람이 분기마다 돌리는 개선   →    LLM이 상시로 돌리는 무한 루프 (수집→학습→추론→환류)
                                  = 정확한 예측을 만드는 플랫폼
```

- 계보: 일본 생산관리 고전(다품종소량·수주생산, 5S·눈으로 보는 관리·POP) → 『동기ERP』(후쿠시마) → 한국 ERP 30년 → Odoo 기반 지능형 ERP
- 핵심 명제: "현장의 원칙은 변하지 않았다. 그 원칙을 실행하는 주체가 사람의 눈에서 데이터의 루프로 확장되었을 뿐이다."
- DMAIC×LLM 루프: Define(경영 질문)–Measure(수집)–Analyze(학습)–Improve(추론·처방)–Control(표준화·환류)을 LLM이 상시 반복 — 한 바퀴 돌 때마다 예측이 정확해진다.

## 프롤로그 (10p, 14,000자) — 직접 집필

"왜 지금 지능형 AI ERP인가 — 목적과 필요성"
1. 현장의 기억: 3정5S와 눈으로 보는 관리 (저자의 체험 서사)
2. 30년의 역설: 시스템은 늘었는데 왜 여전히 눈으로 확인하는가
3. 3정5S의 재해석: 데이터의 정위치·정품·정량
4. 눈으로 보는 관리의 재해석: 관리판에서 실시간 데이터 가시화로, 그리고 '보는' 것에서 '추론하는' 것으로
5. DMAIC의 재해석: 사람의 개선 사이클을 AI의 상시 루프로
6. LLM 무한 루프: 수집→학습→추론→환류가 만드는 예측 플랫폼
7. 이 책의 목표 선언과 1부 안내

## 제1부. 현장에서 플랫폼으로 — 지능형 ERP 컨설팅 방법론 (70p, 7개 장)

- **1장. ERP 50년과 지능형 ERP: 동기ERP에서 AI ERP까지** (10p, 14,000자) — `01_ch1.md`
  MRP→MRP II→ERP→클라우드→AI ERP 역사(기존 1장 압축 계승). 일본 생산관리의 계보: JIT·간판, 다품종소량·수주생산의 생산관리 고전(5S·눈으로 보는 관리·POP·현장 주도형 경영), 『동기ERP』의 동기생산 사상 — ERP(전사 계획)와 현장 풀(pull)의 역할 분담. 한국 ERP 30년. '지능형 ERP(Intelligent ERP)'의 정의: 기록(SoR)을 넘어 판단(SoI)하는 ERP — 5대 요건(단일 데이터 원천, 의미 기반 통합, 실시간 수집, 학습·추론 루프, 인간 협업). Odoo가 베이스인 이유.

- **2장. 컨설팅의 출발: 현장 진단과 3정5S — 데이터 품질의 원점** (10p, 14,000자) — `02_ch2.md`
  머리말1의 5S 스텝(정리→정돈→청소→청결·규정→습관화)과 3정(정위치·정품·정량)을 원전의 구체 사례(10년 안 쓴 부재, 찾기 로스 격감, 자재 두는 곳 청소, 규정 활성화)와 함께 해설. 이를 데이터에 적용하는 '디지털 3정5S' 컨설팅 방법론: 데이터 정리(불용 코드·중복 코드 폐기), 데이터 정돈(기준정보·코드체계 정비 = 데이터의 정위치 — 같은 볼트가 3개 코드였던 일화 계승), 데이터 청소(오류·결측 클렌징), 데이터 청결(입력 규정·검증 규칙), 데이터 습관화(현장이 데이터를 지키는 문화). 현장 진단 체크리스트(물리 5S 진단 × 데이터 5S 진단 매트릭스). "5S 없이 AI 없다" — 데이터 품질이 모든 학습·추론의 전제라는 논증.

- **3장. 눈으로 보는 관리에서 데이터로 보는 관리로** (10p, 14,000자) — `03_ch3.md`
  머리말1의 눈으로 보는 관리: 관리판·카드(제번·도번·작업명·수량·착수/완료 예정), 작업표·출고표·이동표, 발송(작업수배·분배), 납기순 수주 정렬, 진도관리(기다림 로트 해소, 늦음 회복), 계획 대 실적 대비. 그 디지털 전환: Odoo 칸반(파이프라인)=디지털 관리판, 바코드 작업표(중요 데이터를 바코드에 사전 내장 — 원전의 제조부장 대화 인용), POP(생산시점관리)=작업현장 태블릿·IoT, 수주 데이터 입력 전용계획→일정계획·수배 활용. '보이는 공장'에서 '말하는 공장'으로: 실시간 수집이 이상 감지·자연어 브리핑으로 이어지는 구조. 현장 주도형 통제(후공정 인수 의식)와 영업-공장 정보 공유(1일 2회 페이스 투 페이스 → 실시간 공유 포털). 컨설팅 실행 순서(수주장부 전산화→바코드 작업표→POP→LAN 확장 순서를 Odoo 기반으로 재구성).

- **4장. 부품전개와 일정계획: 제번·추번에서 MRP·APS까지** (10p, 14,000자) — `04_ch4.md`
  머리말1의 생산관리 구조: 부품표(구조형 부품표, 공정과의 재묶음), 제번 방식(제조번호로 전 공정 관리) vs 추번 방식, 정미소요량 계산과 중간재고관리부문, 대·중·소 일정계획의 3층 구조(중 일정계획의 유연한 수정→소 일정계획·수배 실행), 공수계획(능력과 부하 계산), 여유(버퍼)의 필요, 수주변경 즉응 유연성, 특급품 처리(베테랑 특별처리반). 이를 Odoo로: BOM·MRP(정미소요량 자동), MPS(대일정), frePPLe APS(중·소일정, 유한능력), 재주문 규칙(중간재고), 긴급 오더 처리. Neck(병목) 공정 탐지와 해소 — 그래프 중심성 분석 예고. 다품종소량·수주생산에서 계획 정확도를 만드는 데이터 조건.

- **5장. DMAIC 데이터 루프: 수집·학습·추론의 무한 사이클** (10p, 14,000자) — `05_ch5.md`
  프롤로그 철학의 본격 방법론화. 6시그마 DMAIC의 원리(정의-측정-분석-개선-관리)와 QC 스토리·PDCA와의 관계. 각 단계의 데이터 방법론: Define=경영 질문과 CTQ→KPI 정의 / Measure=3원천 수집(트랜잭션·현장 POP·암묵지)과 측정 시스템 신뢰성(기존 5장 데이터 방법론 계승) / Analyze=학습(통계·ML·그래프 분석, 원인 추론) / Improve=추론·처방(예측 모델, What-if 시뮬레이션, 개선안 생성) / Control=표준화·환류(Odoo 액션으로 반영, 표준 갱신, 관리도 상시 감시). LLM 무한 루프: 사람이 분기 단위로 돌리던 DMAIC를 LLM 에이전트가 상시 반복 — 루프 1회전마다 데이터가 쌓이고 예측 정확도가 개선되는 학습 곡선. 루프의 안전장치: Human-in-the-Loop 승인 게이트, 통계적 검정, 폭주 방지. 사례형 시나리오: 납기지연 문제를 DMAIC 루프가 자동으로 정의→측정→분석→개선→관리하는 2주의 기록.

- **6장. AX 컨설팅 5단계 로드맵: 진단에서 환류까지** (12p, 17,000자) — `06_ch6.md`
  기존 4장(방법론)을 컨설팅 실행 관점으로 확장. 왜 AX 프로젝트는 어려운가. 목표지향 설계(KGI→KPI→데이터→모델, GQM). 5단계 로드맵 상세 — 각 단계마다 ①목적 ②컨설턴트의 실행 항목 ③현장 활동(머리말1의 지혜 접목: 1단계 진단에 5S·눈으로 보는 관리 진단 포함, 사장·공장장의 열의와 평가가 성공 열쇠라는 원전 강조) ④산출물 ⑤성공 판정 ⑥기간·체제: 1단계 진단(경영 질문, 데이터 성숙도, 현장 5S 진단) / 2단계 기반(Odoo 구축, 코드체계=디지털 정돈) / 3단계 적재(데이터·지식·암묵지) / 4단계 지능화(온톨로지·예측 모델·에이전트·DMAIC 루프 가동) / 5단계 환류(현장 환류·학습 루프·성과 평가). 거버넌스(경영자 스폰서십 — 원전의 "사장 혹은 공장장은 프로젝트 추진의 열의를 계속 가지고" 인용), 변화관리와 의식개혁(자기책임·자율인간 — 원전 인용), 실패 요인 10항. 경량 3주 모델.

- **7장. 공정편성의 재구축과 예측 플랫폼의 완성** (8p, 11,000자) — `07_ch7.md`
  머리말1의 최종 단계: 공정편성 재구축(PQ 분석으로 다량품·소량품 그룹 분리, 그룹 테크놀로지, 흐름화, 절차 개선-내/외 절차 분리=SMED, 좋은 리듬), BPR(리엔지니어링 — 백지에서 프로세스 재설계). 이를 디지털 트윈 시뮬레이션으로: 공정편성 대안을 온톨로지 지식그래프 위에서 What-if 시뮬레이션(라인 밸런싱, Neck 해소, 설비 증설 vs 외주). 온톨로지 지식그래프 요약(기존 6장 핵심 압축: Gruber 정의, GraphRAG, 디지털 트윈 3요소)과 예측 플랫폼 아키텍처 총괄(Odoo+frePPLe+n8n/Dify+Neo4j — 1부의 결론 그림). 성숙도 5단계와 1부 전체 요약, 2부 예고.
