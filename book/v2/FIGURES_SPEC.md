## 1. 공통 스타일 가이드

### 1.1 판형과 규격
| 항목 | 값 |
|------|-----|
| 책 판형 | 신국판 152×225mm, 본문 조판폭 116mm |

| 파일명 | `fig_<장>-<번호>_<영문슬러그>` 예: `fig_12-3_picking` |

### 1.2 색상 팔레트 (본문 인쇄 4도 기준)
| 역할 | 색 | HEX |
|------|-----|-----|
| 주색(제목·주요 박스 테두리·강조) | 딥 네이비 | `#1E2761` |
| 보조 1(프로세스·화살표·긍정 강조) | 틸 | `#028090` |
| 보조 2(옅은 박스 배경) | 아이스 블루 | `#E8F0FB` / 진한 `#CADCFC` |
| 경고·환류·루프(되돌아가는 흐름) | 테라코타 | `#B85042` |
| 본문 텍스트·설명 | 그레이 | `#5A6472` |
| 중립 배경 | 라이트 그레이 | `#EEF1F5` |
- 원칙: 네이비가 60~70% 지배, 틸이 흐름·진행, 테라코타는 "환류·경고·루프"에만. 3색 이상 혼용 금지(그림당 주색+보조 1~2색).
- 그레이스케일 변환 시 명도차가 유지되는지 확인(네이비 20%, 틸 45%, 아이스 92% 수준).

### 1.3 타이포그래피
| 요소 | 폰트·크기(완성 크기 기준) |
|------|--------------------------|
| 그림 내 제목 | 나눔고딕(또는 KoPubWorld돋움) Bold 11~12pt |
| 부제·설명 문장 | 같은 서체 Regular 7.5~8pt, 그레이 |
| 박스 표제 | Bold 8.5~9.5pt |
| 박스 내 항목 | Regular 7~7.5pt |
| 하단 캡션 각주 | Regular 6.5~7pt, 그레이 |
- 영문·숫자는 같은 서체로 통일(별도 영문 서체 금지). 본문 조판 캡션("그림 N-N. …")은 편집부 스타일을 따르므로 그림 안에 캡션 중복 금지 — 그림 안에는 제목만.

### 1.4 도형·선 규칙
- 박스: 라운드 사각형(모서리 R 2.5~3.5mm), 테두리 0.4~0.5mm. 채움은 아이스/라이트 그레이, 핵심 박스만 네이비·틸 솔리드+흰 글자.
- 화살표: 실선 0.5~0.7mm, 삼각 머리. 정방향 흐름=네이비 또는 틸, 환류·루프=테라코타 파선(3:2).
- 아이콘: 라인 아이콘 1.5px 스트로크 계열로 통일(채움 아이콘 금지). 필요 그림에만 최소 사용.
- 금지: 그림자 남용, 그라데이션, 3D 효과, 클립아트, 배경색 전면 채움.

### 1.5 용어 표기 (그림 내 문안 일관성)
3정5S / 눈으로 보는 관리 / DMAIC(정의·수집·학습·추론·환류) / 서드브레인 / 1st·2nd·3rd Brain / Odoo / frePPLe / n8n / Dify / Neo4j / LLM / 5 Space × 6 Station / PTGDA / TA / OWL / HITL / War Room — 띄어쓰기·대소문자 위 표기 그대로.

## 2. 1순위 6점 — 시안 있음 (시안 준수 + 완성도 향상)

각 항목: 배치 위치 / 시안 파일 / 핵심 메시지 / 디자이너 개선 포인트.

### 그림 P-3. DMAIC × LLM 무한 루프
- 위치: 프롤로그 7절 / 시안: `fig_P3_dmaic_loop.(svg|png)`
- 메시지: 5단계(Define 정의→Measure 수집→Analyze 학습→Improve 추론→Control 환류)가 원형으로 순환하고, 중심의 LLM이 상시로 돌린다. 1회전마다 예측이 정확해진다.
- 구성: 원주 위 5개 라운드 박스(영문+국문+도구 한 줄), 시계방향 곡선 화살표(틸), 중앙 네이비 원 "LLM 무한 루프". 하단 각주: 안전장치 3종(HITL·통계 검정·감사 로그).
- 개선 포인트: 화살표 곡률을 완전한 원호로 정리, 회전을 암시하는 나선 잔상(옅은 틸) 추가 검토. 하단 두 박스(Analyze·Improve) 사이 화살표가 박스에 닿지 않게.

### 그림 6-1. AX 컨설팅 5단계 로드맵
- 위치: 1부 6장 6.3절 / 시안: `fig_61_roadmap.(svg|png)`
- 메시지: 진단(2~4주)→기반(4~8주)→적재(4~8주)→지능화(8~12주)→환류(상시)의 실행 순서와 단계별 핵심 활동·산출물. 환류에서 진단으로 되돌아가는 학습 루프.
- 구성: 5개 셰브런(화살촉형 띠, 4단계만 네이비 강조·나머지 틸) + 각 단계 아래 [핵심 활동] 박스와 [산출물] 박스 2단. 하단 테라코타 파선 회귀 화살표 "학습 루프 — 환류의 결과가 다음 진단의 입력이 된다".
- 개선 포인트: 세로가 큰 그림이므로 상하 여백 압축. 셰브런 연결부 정밀 정렬.

### 그림 7-3. 예측 플랫폼 통합 아키텍처
- 위치: 1부 7장 7.4절 / 시안: `fig_73_platform.(svg|png)`
- 메시지: 현장(1st Brain)→Odoo 실행 원장(2nd)→계획(frePPLe)→AX(n8n·Dify)→지식(Neo4j+LLM, 3rd)→경영의 질문까지 6개 층. 왼쪽 위로 "데이터는 위로(ETL)", 오른쪽 아래로 "판단은 아래로(환류)".
- 구성: 가로 전폭 층위 박스 6개 세로 적층(위 2개 층은 네이비·틸 솔리드+흰 글자), 좌우 대형 수직 화살표(틸↑·테라코타↓).
- 개선 포인트: 층간 간격 균일화, 층 이름과 구성요소의 위계(크기 대비) 강화.

### 그림 8-1. 가치사슬 위의 Odoo 모듈 지도
- 위치: 2부 8장 8.5절 / 시안: `fig_81_module_map.(svg|png)`
- 메시지: 고객 접점→영업→조달→물류→생산→재무의 가치사슬 위에 모듈과 장 번호(9~14장)를 배치하고, 그 아래 전폭 밴드 3개(지능 계층 15장 / 확장 부스터 16장 / 단일 PostgreSQL 8장).
- 구성: 상단 6개 카드(헤더 네이비 탭+본문+장 번호), 카드 사이 틸 화살표, 하단 밴드 3개(아이스/틸/네이비).
- 개선 포인트: 카드 헤더 탭의 라운드 처리 정리(시안은 탭 모서리가 어색함), 밴드와 카드 사이 시각적 연결(가는 수직 점선) 추가 검토.

### 그림 21-3. Odoo × JEDAIX 통합 아키텍처 — 3뇌 구조
- 위치: 3부 21장 21.6절 / 시안: `fig_213_odoo_jedaix.(svg|png)`
- 메시지: 좌 Odoo(2nd Brain, 형식지의 원장), 우 JEDAIX(3rd Brain, 암묵지의 발굴·판단), 상단 융합 판단(출력), 하단 현장·사람(1st Brain, HITL). 좌→우 "트랜잭션·이벤트", 우→좌 "확정 판단·규칙 환류"의 쌍방향 루프.
- 구성: 4개 대형 박스 다이아몬드형 배치 + 6개 방향 화살표(네이비/틸 구분) + 화살표 라벨.
- 개선 포인트: **가로 화살표 라벨("트랜잭션·이벤트", "확정 판단·규칙 환류")이 시안에서 화살표·박스에 겹침 — 라벨을 화살표 위/아래로 완전히 분리**. 이 그림은 표지 후보이므로 마감 품질 최우선.

### 그림 E-1. 서드브레인 — 세 갈래 길의 합류
- 위치: 에필로그 '합류' 절 / 시안: `fig_E1_thirdbrain.(svg|png)`
- 메시지: Odoo(기업의 기록·제2부)·온톨로지(기업의 의미·제3부)·LLM 루프(기업의 언어·제1부) 세 원이 겹치는 중심에 서드브레인. 하단에 책의 마지막 문장 인용.
- 구성: 벤다이어그램 3원(네이비/틸/테라코타, 채움 투명도 15%) + 중앙 네이비 원. 
- 개선 포인트: 세 원의 겹침 면적 균등, 원별 라벨의 원 내 배치 최적화. 인쇄 시 투명도 겹침 색 확인.

## 3. 2순위 8점 — 신규 제작 (상세 명세)

### 그림 P-2. 물리 3정5S ↔ 데이터 3정5S 대응도 (프롤로그 4절)
좌우 2단 대응도. 좌측 "공장" 패널(선반·부품·관리판의 미니 라인 일러스트), 우측 "데이터베이스" 패널(테이블·필드·코드의 미니 도식). 가운데에 8행 대응 화살표: 정위치↔코드체계, 정품↔입력 규칙, 정량↔실시간 수집·실사, 정리↔불용코드 폐기, 정돈↔기준정보, 청소↔클렌징, 청결↔검증 규칙, 습관화↔데이터 문화. 각 행 한 줄 라벨, 화살표는 틸.

### 그림 3-1. 관리판 → 칸반 보드 대응도 (1부 3장)
좌: 벽걸이 관리판 일러스트(가로 공정·세로 제번 격자, 자석 카드 3~4장 — 카드에 제번·도번·수량·납기 4항목 표기). 우: Odoo 칸반 화면 도식(3~4개 컬럼, 카드형 UI). 좌우 카드 사이 점선 화살표로 "같은 정보 구조"임을 표시. 하단 한 줄: "판이 곧 보고서였다 — 화면이 곧 관리판이다".

### 그림 4-2. 대·중·소 일정계획 3층 구조 (1부 4장)
3층 수평 띠: 대일정(월 단위, 수주~출하 전체), 중일정(주 단위, 공정 배분), 소일정(일 단위, 작업자·설비 배정). 좌측에 층별 주기·담당 라벨. 우측에서 "수주 변경" 번개 아이콘이 중일정으로 진입해 소일정으로 전파되는 테라코타 화살표. 하단: Odoo MPS/frePPLe 대응 표기.

### 그림 12-1. 이중 기록 재고 개념 (2부 12장)
복식부기 비유. 상단: "위치 A −100 / 위치 B +100"이 한 이동 전표로 동시에 기록되는 T계정형 도식 2개. 하단: 이동 경로(공급업체→입고→보관→생산→출하→고객)를 따라 수량이 소멸하지 않고 위치만 바뀌는 띠 그림. 핵심 문안: "재고는 사라지지 않는다. 위치를 바꿀 뿐이다."

### 그림 13-1. OEE 폭포 차트 (2부 13장)
폭포(waterfall) 차트: 총가용시간 100% 막대에서 계획정지·고장정지(→가동률), 속도 손실·소정지(→성능), 불량·재작업(→품질)이 차례로 깎여 OEE 잔여 막대에 도달. 각 손실 구간 테라코타 계열, 잔여 OEE는 틸. 우측에 OEE=A×P×Q 산식.

### 그림 18-1. ERP의 조명과 사각지대 (3부 18장)
개념 일러스트. 무대 조명(네이비 광원)이 비추는 밝은 영역 안에 "등록된 객체·정의된 관계·트랜잭션"(정형 아이콘들), 조명 밖 어둠에 "베테랑의 감·부서 관행·구두 결정·회색지대"(흐린 실루엣). 어둠 영역에서 새어 나오는 테라코타 손실 화살표 3개(결품·중복 발주·납기 지연). 문안: "손실은 시스템이 비추지 않는 곳에서 발생한다."

### 그림 19-1. JEDAIX 전체 파이프라인 (3부 19장)
세로 적층 7층: 입력 데이터 → Frame(공통 메타데이터 스키마) → 6 Station 대화 → PTGDA → 온톨로지(OWL) → Agent Workflow → Workspace(운영). 층 사이 짧은 화살표, 우측에 각 층 한 줄 설명. 5층(온톨로지)만 틸 솔리드 강조. 스타일은 그림 7-3과 동일 계열로 통일(두 그림이 1·3부에서 서로 호응).

### 그림 20-1. Seed 성장 사슬 (3부 20장)
좌→우 성장 단계도(씨앗→새싹→나무 은유 아이콘 병기): 현장의 말(발화) → Linguistic Seed → Semantic Seed(TA 코드) → SEED_HYPOTHESIS(가설) → Ontological Seed(확정) → OWL Class·Property. 각 단계 아래 실제 예시 한 줄("지난달 C라인에서 두 번…" → … → InventoryRisk 클래스). 확정 단계에 HITL 승인 게이트 아이콘(사람 실루엣+체크).
