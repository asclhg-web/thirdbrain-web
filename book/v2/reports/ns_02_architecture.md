# 제4장. 참조 아키텍처: 뉴로-심볼릭 의사결정 플랫폼의 8계층

> "우리에게 필요한 것은 병에 든 두 시스템이다 — 빠르고 직관적인 System 1과, 느리고 논리적인 System 2가 한 기계 안에서 협력하는 구조다." — Henry Kautz, AAAI Robert S. Engelmore 기념 강연 (2020)의 문제의식을 요약

앞의 세 장이 뉴로-심볼릭 AI의 세 기둥 — 의미적 데이터 패브릭, 설명 가능한 AI, 융합 추론 — 을 각각 원리와 데이터 요건의 수준에서 다루었다면, 이 장은 그 세 기둥을 하나의 건축물로 조립한다. 목표는 특정 제품의 소개가 아니라 참조 아키텍처(reference architecture)다. 어떤 기업이든 자기 스택을 이 참조 구조에 비추어 "우리는 어느 계층을 갖추었고 어느 계층이 비어 있는가"를 판독할 수 있는 좌표계를 제공하는 것이다. 결론을 미리 말하면 뉴로-심볼릭 의사결정 플랫폼은 여덟 개의 계층으로 구성되며, 그 여덟 계층의 절반은 이미 통상적인 지능형 ERP 아키텍처와 겹친다. 뉴로-심볼릭이 더하는 것은 새로운 탑이 아니라, 기존 탑의 특정 층 — 심볼릭 검증과 설명·거버넌스 — 의 보강이다.

## 4.1 전체 조감: 여덟 개의 계층

여덟 계층을 아래(현실 세계)에서 위(거버넌스)로 쌓은 전체 구조를 먼저 텍스트 다이어그램으로 놓는다.

```
┌──────────────────────────────────────────────────────────────────┐
│ ⑧ 설명·거버넌스 계층                                                │
│    추론 경로 기록 │ 근거 UI·설명 리포트 │ 감사 로그 │ 모델·규칙 버전 관리 │
├──────────────────────────────────────────────────────────────────┤
│ ⑦ 융합 오케스트레이션 계층                                           │
│    의사결정 루프: 제안 → 검증 → 설명 → 승인(HITL) → 실행 → 관측        │
│    에이전트 워크플로 엔진 │ 뉴럴↔심볼릭 호출의 지휘                     │
├───────────────────────────┬──────────────────────────────────────┤
│ ⑤ 뉴럴 엔진                │ ⑥ 심볼릭 엔진                          │
│    LLM(생성·요약·번역)      │    비즈니스 규칙 엔진(조건-결과)          │
│    예측 ML(수요·리드타임)    │    제약 검증(SHACL)                    │
│    임베딩·벡터 검색         │    OWL 추론기(공리 기반 연역)             │
│    이상 감지               │    최적화 솔버(LP·CP)                   │
├───────────────────────────┴──────────────────────────────────────┤
│ ④ 지식그래프 계층                                                   │
│    온톨로지 스키마(클래스·관계·공리) + 인스턴스(실데이터)               │
│    속성그래프 또는 RDF/OWL │ GraphRAG의 무대                         │
├──────────────────────────────────────────────────────────────────┤
│ ③ 의미적 데이터 패브릭                                               │
│    시맨틱 카탈로그(용어집·코드체계) │ 데이터 가상화 │ 계보(lineage)      │
├──────────────────────────────────────────────────────────────────┤
│ ② 단일 원장(운영 데이터베이스)                                        │
│    트랜잭션의 진실 원천(SoR) — 판매·구매·재고·제조·회계                 │
├──────────────────────────────────────────────────────────────────┤
│ ① 수집 계층                                                        │
│    트랜잭션 입력 │ POP·바코드·IoT 센서 │ 문서·이메일 │ 현장의 발화       │
└──────────────────────────────────────────────────────────────────┘
      환류: 데이터는 위로(수집→의미→판단) │ 판단은 아래로(승인→원장 환류)
```

이 그림에서 뉴로-심볼릭의 고유성은 ⑤와 ⑥이 나란히 놓여 있고, ⑦이 그 둘을 오가며 지휘하고, ⑧이 그 전 과정을 기록한다는 데 있다. 뉴럴 엔진만 있는 아키텍처는 유창하지만 검증되지 않고, 심볼릭 엔진만 있는 아키텍처는 엄밀하지만 경직된다. 카우츠가 AAAI 강연에서 제시한 뉴로-심볼릭의 유형학(Kautz, 2022)과 서베이 연구들(Garcez & Lamb, 2023; Hitzler et al., 2022)이 공통으로 확인하는 것은, 실용적 시스템의 표준형이 "뉴럴이 제안하고 심볼릭이 검증한다(Neuro → Symbolic 검사기)" 구조라는 점이다. 이 참조 아키텍처의 ⑤⑥⑦은 그 표준형을 기업 의사결정의 스케일로 옮긴 것이다.

## 4.2 계층별 해부

### ① 수집 계층: 네 개의 입구

모든 판단의 원료는 네 종류의 입구로 들어온다. 첫째, 트랜잭션 — 견적·수주·발주·입고·작업지시·전표처럼 업무 수행 자체가 만드는 정형 데이터다. 둘째, 현장 신호 — POP(생산시점관리) 단말과 바코드 스캔, IoT 센서가 물리적 사건(착수·완료·정체·온도·진동)을 발생 시점에 포착한다. 셋째, 문서 — 도면, 계약서, 이메일, 검사성적서 같은 비정형·반정형 자료다. 넷째, 발화 — 현장 담당자의 말과 노트, 구조화 인터뷰의 응답이다. 네 번째 입구가 낯설게 보일 수 있으나, 뉴로-심볼릭의 관점에서는 결정적이다. 심볼릭 계층의 규칙과 공리의 상당수는 처음부터 형식 언어로 존재하지 않고 베테랑의 경험칙 속에 있으며(Polanyi, 1966), 발화를 수집하지 않는 플랫폼은 검증 계층에 채워 넣을 규칙의 원천 하나를 스스로 끊는 것이다.

수집 계층의 품질 요건은 두 가지다. 기록이 작업의 일부가 되어 수집 행위 자체가 소멸할 것, 그리고 모든 입력이 시점·주체·출처의 메타데이터를 갖고 들어올 것. 후자가 없으면 ⑧계층의 추론 경로 기록이 원천에서 끊긴다.

### ② 단일 원장: 진실은 한 곳에

수집된 트랜잭션이 적재되는 곳이 단일 원장 — 기록 시스템(System of Record)으로서의 운영 데이터베이스다. 원칙은 단순하다. 하나의 사실은 한 곳에만 기록되고, 다른 모든 계층은 그것을 참조하거나 파생시킬 뿐 복제된 마스터를 갖지 않는다. 품목·거래처·BOM의 사본이 시스템마다 생기는 순간, 위 계층의 어떤 정교한 추론도 "어느 사본이 맞는가"라는 원초적 질문 앞에서 무너진다. 뉴로-심볼릭 문헌이 지식그래프와 추론기를 논할 때 이 계층을 당연한 전제로 생략하는 경우가 많지만, 기업 현장에서는 이 전제야말로 가장 자주 무너져 있는 부분이다. 단일 원장이 없는 뉴로-심볼릭은 모래 위의 검증탑이다.

### ③ 의미적 데이터 패브릭: 데이터에 의미의 배선을 깔다

세 번째 계층은 원장의 데이터와 그래프의 지식 사이에 놓이는 의미의 배선층이다. 구성 요소는 셋이다. 첫째, 시맨틱 카탈로그 — 회사의 모든 데이터 자산에 대한 용어집·코드체계·동의어 사전·책임자 정보의 목록이다. "매출"이 영업의 수주액인지 회계의 청구액인지를 사람마다 다르게 이해하는 회사에서, 카탈로그는 그 어휘를 하나로 고정한다. 오픈소스 진영에서는 DataHub와 OpenMetadata가 검색·용어집·태깅·거버넌스를 갖춘 카탈로그의 대표 후보다. 둘째, 데이터 가상화 — 물리적으로 흩어진 원천(원장, 레거시 엑셀, 외부 API)을 복제 없이 하나의 질의 평면으로 묶는 접근이며, 전면 도입이 무겁다면 ETL 파이프라인의 표준화가 실용적 대체물이 된다. 셋째, 계보(lineage) — 어떤 지표와 그래프 노드가 어떤 원천에서 어떤 변환을 거쳐 왔는지의 이력이다. OpenLineage는 리니지 이벤트의 개방 표준이고, Marquez가 그 참조 구현으로서 Airflow·Spark·dbt 등의 파이프라인에서 이벤트를 수집한다.

이 계층이 뉴로-심볼릭에서 갖는 의미는 명확하다. ⑥계층의 검증은 "이 값이 제약을 만족하는가"를 묻지만, ③계층의 계보는 "이 값이 어디서 왔는가"를 답한다. 설명 가능성(XAI)의 절반은 모델의 설명이 아니라 데이터의 설명이며, 계보 없는 근거 제시는 중간부터 시작하는 이야기와 같다.

### ④ 지식그래프: 스키마와 인스턴스의 이중 구조

네 번째 계층이 이 보고서 전체의 허리인 온톨로지 지식그래프다. 구조는 이중이다. 위층은 온톨로지 스키마 — 어떤 클래스(고객·품목·공정·설비·로트)가 존재하고 어떤 관계(공급한다·구성한다·거친다·원인이다)가 허용되며 어떤 공리(모든 작업지시는 정확히 하나의 품목을 갖는다)가 성립하는지에 대한, 그루버의 정의 그대로 "개념화의 명시적 명세"다(Gruber, 1993). 아래층은 인스턴스 — 그 스키마를 실제 데이터로 채운 노드와 관계들이다.

기술 선택지는 크게 둘이다. RDF/OWL 계열(Apache Jena, GraphDB 등)은 W3C 표준 위에서 형식 추론 — 공리로부터의 자동 연역 — 을 지원하는 것이 강점이고, 속성 그래프(property graph) 계열(Neo4j 등)은 경로 탐색·중심성 같은 그래프 알고리즘과 개발 생산성이 강점이다. 중요한 것은 이 선택이 배타적이지 않다는 사실이다. Neo4j의 neosemantics(n10s) 플러그인은 RDF의 가져오기·내보내기와 함께 SHACL 제약을 사이퍼(Cypher) 질의로 번역해 속성 그래프를 검증하는 절차를 제공하므로(Neo4j Labs, n10s 문서), 속성 그래프를 운영 본체로 두고 표준 계열의 검증·추론을 선택적으로 얹는 절충이 실무적으로 성립한다. 이 계층은 또한 GraphRAG — LLM의 검색을 그래프 탐색과 커뮤니티 요약으로 증강하는 기법(Edge et al., 2024) — 의 무대이며, Microsoft GraphRAG 파이프라인의 산출물을 Neo4j에 적재해 검색기로 쓰는 통합 경로와 Neo4j 자체의 graphrag 파이썬 패키지가 모두 공개되어 있다.

### ⑤ 뉴럴 엔진: 패턴의 반구

다섯 번째 계층은 신경망 계열의 능력 일체다. 네 가지 부품으로 나뉜다. LLM은 자연어의 이해·생성·요약과, 자연어↔형식 언어(질의·규칙 초안)의 번역을 맡는다. 예측 ML은 수요·리드타임·불량 같은 연속·이산 표적의 학습 기반 예측을 맡으며, 구현은 그래디언트 부스팅부터 시계열 심층 모델까지 문제의 데이터 두께가 결정한다. 임베딩·벡터 검색은 텍스트·품목·사례의 의미적 유사성 공간을 제공해 "비슷한 과거 사례"의 소환을 가능하게 한다. 이상 감지는 관리도의 통계적 감시를 보완하는 다변량 패턴 감시다. 이 계층의 산출물은 언제나 확률적 후보 — 제안, 추정, 유사 사례 — 이며, 그 지위가 확정으로 바뀌는 곳은 이 계층이 아니라 ⑥과 ⑦이라는 것이 아키텍처 전체의 규율이다.

### ⑥ 심볼릭 엔진: 검증의 반구

여섯 번째 계층이 뉴로-심볼릭을 뉴로-온리와 구별 짓는 심장이다. 네 가지 부품이 서로 다른 종류의 형식적 판정을 맡는다.

첫째, 비즈니스 규칙 엔진이다. "여신 한도를 초과한 고객의 수주는 영업이사 승인을 요한다" 같은 조건-결과 규칙을 코드가 아니라 선언적 자산으로 관리하고 평가한다. Java 진영의 표준은 Drools — 전방·후방 연쇄 추론과 복합 이벤트 처리를 갖추고, 의사결정 표준 표기인 DMN(Decision Model and Notation)을 적합성 레벨 3까지 지원하는 Apache 산하의 오픈소스 엔진이다(Apache KIE, Drools 문서). 규칙 엔진의 계보는 포기의 Rete 알고리즘(Forgy, 1982)까지 올라가며, 수천 개 규칙의 효율적 평가라는 문제는 40년 전에 이미 풀려 있는 문제라는 점이 중요하다 — 어려운 것은 평가가 아니라 규칙의 획득과 관리다.

둘째, 제약 검증이다. W3C 표준 SHACL(Shapes Constraint Language)은 그래프 데이터가 갖추어야 할 형상(shape) — 필수 속성, 카디널리티, 값 범위, 패턴 — 을 선언하고 위반을 보고서로 산출한다(Knublauch & Kontokostas, 2017). OWL 추론이 "공리로부터 무엇이 따라 나오는가"를 묻는 열린 세계(open world)의 도구라면, SHACL은 "이 데이터가 계약을 지키는가"를 묻는 닫힌 검사의 도구이며, 기업 데이터 품질의 문법으로는 후자가 먼저다. 구현은 RDF 진영의 pySHACL·Jena, 속성 그래프 진영의 n10s가 있다.

셋째, OWL 추론기다. 클래스 포섭·일관성 검사·속성 전이 같은 논리적 연역을 자동화한다. 완전한 OWL 2 DL 추론은 최악의 경우 지수적 복잡도를 가지므로(HermiT — Glimm et al., 2014; Pellet), 실무에서는 표현력을 제한한 프로파일 — 대규모 클래스 계층에 특화된 EL의 ELK, 규칙 기반 실체화가 가능한 OWL 2 RL — 로 성능을 확보하는 것이 정석이다. 기업 의사결정 플랫폼에서 추론기의 실용적 용도는 심오한 정리 증명이 아니라, 스키마의 모순 탐지와 계층 관계의 자동 완성이라는 소박하지만 꾸준한 역할이다.

넷째, 최적화 솔버다. "제약을 모두 만족하면서 목적 함수를 최소화하는 해"를 구하는 선형계획(LP)·혼합정수계획(MIP)·제약 프로그래밍(CP)의 도구로, 일정 편성·배분·로트 결정처럼 조합적 선택이 큰 문제에서 뉴럴의 직관을 대체 불가능하게 보완한다. Google OR-Tools는 LP 솔버(Glop·PDLP)와 CP-SAT — 제약 프로그래밍·SAT·MIP 기법을 결합한 하이브리드 솔버 — 를 포함하는 대표적 오픈소스 스위트이며 스케줄링·자원 배분에 널리 쓰인다(Google OR-Tools 문서). APS(frePPLe류)의 유한능력 엔진도 이 부품의 도메인 특화형으로 볼 수 있다.

### ⑦ 융합 오케스트레이션: 두 반구를 잇는 뇌량

일곱 번째 계층은 ⑤와 ⑥을 하나의 의사결정 루프로 엮는 지휘부다. 표준 루프는 여섯 박자다. 제안 — 뉴럴 엔진이 그래프의 컨텍스트(GraphRAG) 위에서 판단 후보를 생성한다. 검증 — 심볼릭 엔진이 후보를 제약·규칙·솔버로 검사하고, 위반이 있으면 위반 항목과 함께 반려해 재생성시킨다. 설명 — 통과한 후보에 대해 "어떤 데이터, 어떤 규칙, 어떤 계산이 이 결론을 지지하는가"의 근거 패키지를 조립한다. 승인 — 사람이 근거 패키지를 보고 승인·수정·반려한다(HITL). 실행 — 승인된 판단이 원장의 파라미터·트랜잭션으로 환류된다. 관측 — 실행의 결과가 다시 수집 계층으로 들어와 다음 회전의 학습 재료가 된다. 구현 기술은 워크플로 엔진(n8n류)과 에이전트 프레임워크(Dify·LangGraph류)의 조합이 현재의 실무 표준이며, 핵심 설계 원칙은 검증 통과를 다음 박자로 넘어가는 형식 요건으로 강제하는 것 — 뉴럴의 산출이 심볼릭의 관문을 우회할 수 있는 뒷길을 아키텍처 수준에서 없애는 것이다.

### ⑧ 설명·거버넌스 계층: 판단의 등기소

마지막 계층은 위의 모든 활동을 재구성 가능한 기록으로 남긴다. 네 부품이다. 추론 경로 기록 — 하나의 판단에 대해 입력 데이터(계보 포함), 호출된 모델과 버전, 평가된 규칙과 결과, 통과·위반의 이력을 구조화된 로그로 남긴다. 근거 UI — 그 기록을 의사결정자가 읽을 수 있는 형태(근거 그래프의 시각화, 규칙 판정표, 유사 사례 목록)로 제시한다. 감사 로그 — 누가 언제 무엇을 승인·수정·반려했고 이유가 무엇이었는지의 불변 기록이다. 모델·규칙 버전 관리 — 모델 가중치와 규칙 집합, 온톨로지 스키마 각각의 버전과 배포 이력을 관리해 "그 시점의 판단은 그 시점의 어떤 지식으로 내려졌는가"를 소급 가능하게 한다. 이 계층은 규제 대응(EU AI Act류의 고위험 AI 문서화 요구)의 층이기 이전에 학습의 층이다 — 기록되지 않는 판단은 개선의 입력이 될 수 없다.

## 4.4 한 건의 의사결정이 8계층을 통과하는 길: 긴급 수주 수락 판단

참조 아키텍처는 정지 화면이 아니라 동선으로 이해될 때 비로소 의미를 갖는다. 가상의 부품가공기업에 걸려온 전화 한 통 — "품목 X 500개, 10일 안에 받을 수 있습니까? 단가는 8% 더 드리겠습니다" — 가 여덟 계층을 통과하는 길을 따라가 보자.

①수집. 영업 담당이 통화 내용을 시스템에 등록한다. 품목·수량·희망 납기·제안 단가가 정형 필드로, "이 고객은 이번 건이 잘되면 연간 계약을 논의하겠다고 함"이라는 발화 맥락이 비정형 메모로 함께 들어온다. ②단일 원장. 견적 초안이 원장에 생성되고, 고객의 여신·과거 주문·미수 현황이 같은 데이터베이스에서 즉시 참조된다. ③패브릭. 시맨틱 카탈로그가 "납기"를 수주 확정 납기(출하 기준)로 해석하도록 어휘를 고정하고, 이후 판단에 쓰일 데이터들의 계보 — 표준시간이 언제 개정된 값인지, 재고 수량이 몇 분 전 스냅숏인지 — 를 근거 패키지에 첨부할 수 있게 준비한다.

④지식그래프. 품목 X의 BOM 전개, 공정 경로, 경로상 설비의 현재 부하, 해당 고객의 과거 지연·클레임 이력이 그래프 탐색 한 번으로 모인다. 경로에 열처리 외주 공정이 포함되어 있고, 그 외주처가 최근 병목이라는 사실이 중심성·부하 데이터로 드러난다. ⑤뉴럴 엔진. 리드타임 예측 모델이 현재 부하 조건에서 품목 X의 완주 소요를 11.5일(80% 신뢰구간 9~14일)로 추정하고, 임베딩 검색이 유사한 과거 긴급 수주 세 건 — 두 건 성공, 한 건 지연 배상 — 을 소환하며, LLM이 이를 종합해 "외주 선행 발주와 로트 분할을 조건으로 수락 가능"이라는 판단 후보와 서사를 생성한다.

⑥심볼릭 엔진. 이제 후보가 검증대에 오른다. SHACL 검증이 판단에 쓰인 데이터의 계약 — 품목 X의 라우팅에 표준시간 결측이 없는가, 고객 노드에 여신 속성이 있는가 — 을 확인한다. 규칙 엔진이 회사의 명문 규칙을 평가한다. "여신 잔여 한도 미만의 신규 수주" 통과, "긴급 할증 수주는 공헌이익률 25% 이상" 통과(8% 할증 반영 시 27%), "납기 10일 미만 수주는 공장장 승인 필수" — 승인 요건 발동. 최적화 솔버(유한능력 일정)가 기존 오더를 지연시키지 않는 삽입 스케줄의 존재를 계산해 "기존 A사 오더 1건이 1일 지연되는 해가 최선"이라는 제약 충돌을 발견한다. OWL 추론기는 스키마 수준에서 이 판단이 참조한 클래스 관계에 모순이 없음을 확인한다. 검증의 결론: 무조건 수락은 규칙 위반이 아니라 제약 충돌이며, 수락하려면 (a) 납기 12일 협상 또는 (b) A사 오더 1일 지연의 트레이드오프 승인이 필요하다.

⑦오케스트레이션. 루프가 뉴럴의 제안을 심볼릭의 판정과 결합해 두 개의 실행 가능한 대안 — 12일 납기 역제안, 또는 A사 조정 전제의 10일 수락 — 으로 정리하고, 각각의 근거 패키지(예측 분포, 유사 사례, 규칙 판정표, 일정 시뮬레이션)를 조립해 공장장의 승인 게이트에 상신한다. 공장장은 A사와의 관계를 아는 사람으로서 12일 역제안을 선택하고, 이유를 한 줄 남긴다. ⑧설명·거버넌스. 이 한 건의 전 과정 — 어떤 버전의 예측 모델과 어떤 버전의 규칙 집합이 어떤 데이터 위에서 어떤 판정을 냈고, 사람이 무엇을 왜 선택했는가 — 이 판단 로그로 등기된다. 4주 뒤 실제 출하가 11일 만에 이루어졌다는 관측이 붙으면, 이 레코드는 예측 모델의 재학습 사례이자 "긴급 수주 역제안" 패턴의 선례가 된다.

주목할 것은 이 동선에서 LLM이 한 일과 하지 않은 일이다. LLM은 맥락을 모으고 후보를 만들고 서사를 썼다 — 그러나 여신을 판정하지 않았고, 일정을 계산하지 않았고, 수락을 결정하지 않았다. 판정은 규칙이, 계산은 솔버가, 결정은 사람이 했다. 환각이 구조적으로 차단된다는 요약(Executive Summary)의 명제는 이 역할 분리의 다른 표현이다.

## 핵심 요약

- 뉴로-심볼릭 의사결정 플랫폼의 참조 아키텍처는 8계층 — ①수집 ②단일 원장 ③의미적 데이터 패브릭 ④지식그래프 ⑤뉴럴 엔진 ⑥심볼릭 엔진 ⑦융합 오케스트레이션 ⑧설명·거버넌스 — 으로 구성되며, 고유성은 ⑤⑥의 병렬과 ⑦⑧의 지휘·기록에 있다.
- 수집 계층의 네 입구(트랜잭션·현장·문서·발화) 중 발화의 수집이 심볼릭 규칙의 원천을 결정하고, 단일 원장 없는 뉴로-심볼릭은 모래 위의 검증탑이다.
- 의미적 데이터 패브릭(카탈로그·가상화·계보)은 "이 값이 어디서 왔는가"를 답하는 층이며, 설명 가능성의 절반은 모델이 아니라 데이터의 설명이다.
- 지식그래프는 스키마(공리)와 인스턴스의 이중 구조다. 속성 그래프를 본체로 두고 n10s류의 브리지로 SHACL 검증·RDF 표준을 얹는 절충이 실무적으로 성립한다.
- 심볼릭 엔진은 규칙 엔진(Drools/DMN), 제약 검증(SHACL), OWL 추론기(ELK·HermiT), 최적화 솔버(OR-Tools)의 네 부품이 서로 다른 형식적 판정을 분담한다.
- 융합 오케스트레이션의 표준 루프는 제안→검증→설명→승인→실행→관측이며, 검증 통과를 형식 요건으로 강제해 뉴럴 산출의 우회로를 없애는 것이 핵심 설계 원칙이다.
- 긴급 수주 시나리오가 보이듯, LLM은 맥락과 후보와 서사를 만들되 판정은 규칙이, 계산은 솔버가, 결정은 사람이 한다 — 이것이 환각의 구조적 차단이다.

# 제5장. 우리 아키텍처와의 매핑: 이미 놓인 뼈대

> "우리는 방향을 바꿀 필요가 없다. 이미 놓인 뼈대 위에 검증 계층과 설명 계층을 더하면 된다." — 본 보고서 요약(Executive Summary)

참조 아키텍처를 세웠으니, 이제 『AI ERP 혁명』 3부작이 설계해 온 실제 스택 — Odoo 단일 원장, n8n·Dify의 AX 부스터, Neo4j 온톨로지, LLM 이중화, frePPLe APS, JEDAIX의 PTGDA·Agent Workflow, DMAIC 무한 루프 — 을 8계층 좌표 위에 겹쳐 놓는다. 이 매핑의 목적은 자화자찬이 아니라 정직한 재고 조사다. 어느 계층이 이미 서 있고, 어느 계층이 부분 시공 상태이며, 어느 계층이 비어 있는가.

## 5.1 8계층 매핑표

| 참조 계층 | 책의 스택 대응 | 판정 |
|------|------|------|
| ① 수집 | **Odoo 트랜잭션 입력, 바코드·POP·IoT(1부 3장), JEDAIX 6 Station의 발화 수집(3부 19장)** | 갖춤 — 발화 입구까지 갖춘 드문 구성 |
| ② 단일 원장 | **Odoo 단일 PostgreSQL — 판매·구매·재고·제조·회계의 SoR(1·2부)** | 갖춤 |
| ③ 의미 패브릭 | n8n ETL 파이프라인과 공통 코드체계(1부 2장, 2부 16장) — 배선은 있으나 카탈로그·계보는 없음 | 부분 |
| ④ 지식그래프 | **Neo4j 온톨로지 지식그래프(GraphRAG), JEDAIX Frame·5 Space·OWL Class(3부 19~20장)** | 갖춤 — 속성 그래프 본체 + OWL 형식화 병행 |

| ⑥ 심볼릭 엔진 | JEDAIX PTGDA 임계 검증·6 결정론 검증 규칙·SWRL Rule·SCM Backbone 8계산기, frePPLe 유한능력 엔진(3부 20~21장) | 부분 — 범용 규칙 엔진·SHACL·추론기·범용 솔버 부재 |

| ⑧ 설명·거버넌스 | HITL 승인 게이트·수정 이유 기록·감사 로그(1부 5.8절), wave/particle 확신도, Harness 권한 검증(3부 20~21장) | 부분 — 기록은 있으나 근거 UI·설명 리포트·버전 관리 미비 |

여덟 칸 중 다섯 칸이 굵은 글씨 — 이미 갖춘 상태 — 다. 그리고 남은 세 칸도 빈 땅이 아니라 부분 시공이다. 이것이 "방향을 바꿀 필요가 없다"는 결론의 근거다. 이하에서 갖춘 것의 의미와 부족한 것의 실체를 차례로 짚는다.

## 5.2 이미 갖춘 것: 세 개의 해석

매핑표를 자세히 보면, 책의 스택은 뉴로-심볼릭의 어휘를 쓰지 않았을 뿐 그 구조를 이미 세 곳에서 실장하고 있다.

첫째, DMAIC 무한 루프는 융합 추론 사이클의 실장이다. 1부 5장이 설계한 루프 — 관리도 이상이 Define을 점화하고, 통계·ML·그래프 분석(Analyze)이 원인을 확정하며, LLM의 개선안 생성과 시뮬레이션 비교(Improve)가 승인 게이트를 거쳐 Odoo로 환류(Control)되는 구조 — 를 참조 아키텍처의 ⑦계층 여섯 박자에 포개면 대응이 정확하다. LLM의 개선안 생성이 '제안'이고, 통계적 검정의 형식 요건화와 frePPLe 시뮬레이션이 '검증'이며, 근거·성적표를 동반한 상신이 '설명'이고, HITL 게이트가 '승인', Odoo 환류가 '실행', 관리도 상시 감시가 '관측'이다. 5장이 "그럴듯한 설명이 통계적 근거를 대체하지 못하도록 검정 통과를 단계 전환의 형식 요건으로 강제한다"고 쓴 문장은, 뉴로-심볼릭 문헌이 말하는 "뉴럴 제안에 대한 심볼릭 게이트"의 정의 그 자체다. 우리는 융합 추론을 방법론의 이름(DMAIC)으로 먼저 세웠고, 이제 그 검증 박자에 형식적 부품을 채워 넣으면 된다.

둘째, PTGDA는 뉴럴→심볼릭 지식 추출의 실장이다. 뉴로-심볼릭 연구의 오랜 과제 하나는 신경망적·비정형적 원천에서 심볼릭 지식을 획득하는 경로 — 전문가시스템 시대 이래의 지식 획득 병목 — 다. 3부 20장이 해부한 JEDAIX의 파이프라인은 정확히 이 경로의 산업적 구현이다. LLM이 발화를 Chunk로 분해하고(뉴럴), TA 유형학이 신호를 분류하며, 반복 확인의 확신도(wave)가 임계(70%·3회)를 넘을 때만 OWL Class와 SWRL Rule로 확정(particle)된다(심볼릭). LLM은 번역 계층일 뿐 확정 판단을 갖지 않는다는 20장의 원칙은, 뉴럴의 확률적 산출이 심볼릭 자산으로 승격되는 관문에 통계적 규율과 사람의 승인을 세운 것으로, 참조 아키텍처 ⑥계층의 '규칙 집합'이 어디서 오는가에 대한 답 — 규칙은 손으로 쓰는 것이 아니라 현장의 발화에서 검증을 거쳐 자라는 것 — 을 이미 제공하고 있다.

셋째, HITL·감사 구조는 거버넌스 계층의 실장이다. 1부 5장의 3중 안전장치(승인 게이트·검정 요건·서킷 브레이커와 감사 로그), 3부 20장의 자격 검증(Harness)과 판단 승인(사람)의 분리, 21장의 Digital Twin 시뮬레이션 후 승인 원칙은 ⑧계층의 뼈대다. 특히 "수정·반려의 이유를 기록하고 다음 제안에 반영한다"는 설계는 거버넌스 기록을 규제 대응용 사본이 아니라 학습의 입력으로 삼는다는 점에서, 참조 아키텍처가 요구하는 "판단의 등기소"의 정신을 이미 담고 있다.

## 5.3 부족한 것: 네 개의 공백

정직한 재고 조사의 나머지 절반이다. 네 가지 공백을 실체 수준에서 명시한다.

(a) 심볼릭 검증의 형식화 — SHACL과 범용 규칙 엔진의 부재. 현재의 검증은 세 곳에 흩어져 있다. n8n 파이프라인 안의 데이터 검증 규칙(1부 2장의 3정5S 검증), JEDAIX의 6가지 결정론 검증 규칙(참조 무결성·승인자 자격 등)과 SWRL 계층, 그리고 DMAIC 루프의 통계 검정. 각각은 유효하지만, 그래프 전체에 대한 선언적 제약 언어(SHACL 셰이프)로 표준화되어 있지 않고, 비즈니스 규칙이 파이프라인 코드·JEDAIX 내부·Odoo 자동화 규칙에 분산되어 단일한 규칙 대장(rule repository)이 없다. 검증이 흩어져 있으면 "이 판단이 통과한 검증의 전체 목록"을 제시할 수 없고, 그것은 곧 설명 가능성의 상한이 된다.

(b) 설명 계층의 제품화 — 근거는 있으나 근거 UI가 없다. GraphRAG는 근거 노드를 반환하고, 루프는 성적표를 상신하며, 승인 이력은 기록된다. 그러나 이 조각들이 "판단 한 건의 근거 패키지"라는 단일 제품 — 데이터 계보, 규칙 판정표, 예측 신뢰구간, 유사 선례, 반사실("무엇이 달랐다면 결론이 바뀌었는가")을 한 화면에 조립한 설명 리포트 — 으로 묶여 있지 않다. 추론 경로는 존재하되 로그의 형태로 존재하며, 로그는 감사인의 것이지 의사결정자의 것이 아니다.

(c) 시맨틱 카탈로그와 계보 관리의 부재. 공통 코드체계(2장)와 온톨로지 스키마 정의서(16장)는 카탈로그의 씨앗이지만, 전사 데이터 자산의 검색 가능한 목록·용어집·책임자·품질 지표를 담는 카탈로그 제품과, n8n 파이프라인의 변환 이력을 표준 이벤트(OpenLineage류)로 남기는 계보 관리가 없다. 현재 구조에서 "이 KPI 값은 어느 원천의 어느 시점 데이터가 어떤 변환을 거친 것인가"는 파이프라인을 읽을 줄 아는 사람만 답할 수 있다.

(d) 최적화 솔버의 일반화. frePPLe의 유한능력 엔진은 생산 일정이라는 도메인에 특화된 솔버이며 그 영역에서는 충분하다. 그러나 배송 묶음·자금 배분·인력 편성·복수 목적의 트레이드오프처럼 일정 밖의 조합 최적화 질문에는 범용 솔버(LP·MIP·CP-SAT)의 자리가 비어 있다. 뉴럴이 "좋아 보이는 안"을 내는 문제와 솔버가 "최적해"를 내는 문제를 구분하는 감각이 아직 아키텍처에 제도화되어 있지 않다.

요컨대 우리의 골격은 ①②④⑤⑦이 서 있고 ⑥⑧이 부분 시공이며 ③이 가장 얇다. 그리고 이 진단은 그대로 다음 장의 로드맵이 된다.

## 핵심 요약

- 책의 스택을 8계층에 매핑하면 다섯 계층(수집·단일 원장·지식그래프·뉴럴 엔진·오케스트레이션)은 이미 갖추었고, 세 계층(의미 패브릭·심볼릭 엔진·설명 거버넌스)은 부분 시공 상태다.
- DMAIC 무한 루프는 융합 추론 사이클의 실장이다 — 제안(LLM)·검증(검정·시뮬레이션)·설명(성적표)·승인(HITL)·실행(Odoo 환류)·관측(관리도)의 여섯 박자가 이미 돌고 있다.
- PTGDA는 뉴럴→심볼릭 지식 추출의 실장이다 — 발화를 LLM이 분해하고 반복 확인의 임계와 사람의 승인을 거쳐 OWL Class·SWRL Rule로 확정하는 구조는 지식 획득 병목에 대한 산업적 답이다.
- HITL 승인 게이트·수정 이유 기록·Harness 자격 검증·감사 로그는 거버넌스 계층의 뼈대이며, 기록을 학습의 입력으로 삼는 정신까지 갖추고 있다.
- 공백은 넷이다: (a) SHACL·규칙 대장으로의 검증 형식화 (b) 근거 UI·설명 리포트의 제품화 (c) 시맨틱 카탈로그·계보 관리 (d) 범용 최적화 솔버의 통합.
- 결론적으로 방향 전환은 불필요하다. 부분 시공된 ③⑥⑧을 채우는 보강 공사가 다음 장의 로드맵이다.

# 제6장. 보강 로드맵과 데이터 준비 체크리스트

> "완벽함이란 더 이상 더할 것이 없을 때가 아니라, 더 이상 뺄 것이 없을 때 달성된다." — Antoine de Saint-Exupéry, *Terre des Hommes* (1939)

5장의 재고 조사가 확인한 네 개의 공백을 어떤 순서로, 얼마의 기간에, 무엇을 성공 판정으로 삼아 메울 것인가. 이 장은 3단계 보강 로드맵과 15항의 데이터 준비 체크리스트, 그리고 이 보강이 요구하는 비용에 대한 정직한 평가를 제시한다. 로드맵의 설계 원칙은 책 전체의 성숙도 사다리와 동일하다 — 각 단계는 다음 단계의 데이터를 낳고, 단계를 건너뛰면 위 단계는 장식이 된다.

## 6.1 3단계 보강 로드맵

### 1단계: 판단 이력의 축적과 제약의 선언 (약 0~6개월)

첫 단계는 새 엔진의 도입이 아니라 두 종류의 기록을 시작하는 것이다. 첫째, 판단 로그 스키마의 확정과 축적이다. DMAIC 루프와 JEDAIX 승인 게이트가 이미 남기고 있는 기록 — 제안, 근거, 승인·수정·반려, 이유, 사후 결과 — 을 하나의 표준 스키마(그래프의 판단 노드)로 통일해 쌓는다. 이 로그가 없으면 2단계의 설명 리포트는 조립할 재료가 없고 3단계의 메타인지는 학습할 이력이 없다. 둘째, SHACL 제약의 도입이다. 온톨로지 스키마 정의서를 SHACL 셰이프로 번역하는 것부터 시작한다 — 모든 작업지시는 품목·라우팅·수량을 가져야 한다, 모든 판단 노드는 근거 관계를 하나 이상 가져야 한다 같은 계약을 선언하고, n10s(속성 그래프 경로) 또는 pySHACL(RDF 내보내기 경로)로 야간 배치 검증을 돌려 위반 리포트를 주간 발행한다. 검증은 처음부터 게이트가 아니라 리포트로 시작하는 것이 요령이다 — 위반의 실태를 모른 채 게이트를 세우면 업무가 멈추고, 게이트 없이 리포트만 두면 아무도 보지 않으므로, 리포트로 시작해 위반율이 관리 수준에 들어온 제약부터 차례로 게이트로 승격시킨다.

같은 기간에 시맨틱 카탈로그의 씨앗을 심는다. 무거운 플랫폼 도입 전에, 기존 코드체계 정의서·KPI 정의서·온톨로지 스키마 정의서를 하나의 용어집으로 통합하고 책임자를 지정하는 것만으로 카탈로그의 최소 기능이 선다. 도구가 필요해지는 시점 — 자산 수백 개, 질문하는 사람 수십 명 — 에 OpenMetadata류를 도입해도 늦지 않다.

### 2단계: 규칙 엔진과 설명 리포트의 제품화 (약 6~12개월)

두 번째 단계에서 심볼릭 검증과 설명이 제품이 된다. 첫째, 규칙 대장과 규칙 엔진이다. 세 곳에 흩어진 규칙 — Odoo 자동화 규칙, n8n 파이프라인 검증, JEDAIX SWRL — 의 목록을 만들고, 의사결정에 관여하는 비즈니스 규칙(여신·마진·납기·승인 요건)을 DMN 의사결정 표 또는 Drools 규칙으로 이관해 단일 저장소에서 버전 관리한다. 판정의 실행 위치는 오케스트레이션 루프의 '검증' 박자다 — LLM의 모든 제안은 규칙 엔진의 판정표를 통과 기록과 함께 첨부해야만 승인 게이트에 오를 수 있다는 형식 요건을 n8n 워크플로에 강제한다. 둘째, 설명 리포트의 제품화다. 1단계의 판단 로그와 규칙 판정표, GraphRAG 근거 노드, 예측 신뢰구간, 유사 선례를 한 화면으로 조립하는 근거 UI를 만든다. 구현의 규모보다 계약이 중요하다 — "승인 게이트에 오르는 모든 제안은 다섯 요소(데이터 계보·규칙 판정·예측 근거·선례·반대 논거)를 갖춘 리포트를 동반한다"는 표준이 서면, UI는 Odoo 화면 안의 탭 하나로도 충분히 시작할 수 있다. 셋째, 계보의 표준화다. n8n 파이프라인의 주요 변환에 OpenLineage 이벤트 발행을 붙여, 설명 리포트의 데이터 계보 항목이 수작업 주석이 아니라 자동 수집 기록이 되게 한다.

### 3단계: 융합 오케스트레이션의 고도화와 메타인지 (약 12~24개월)

세 번째 단계는 두 반구의 협업을 정교화한다. 첫째, 범용 솔버의 통합이다. OR-Tools류의 LP·CP-SAT 솔버를 오케스트레이션이 호출 가능한 도구로 등록하고, "조합적 선택이 크고 제약이 명시 가능한 문제는 솔버로 라우팅한다"는 문제 분류 규칙을 세운다. 둘째, 제안-검증 협상 루프다. 검증 실패 시 위반 항목을 LLM에 되먹여 수정안을 재생성시키는 자동 반복(상한 횟수 포함)을 구현해, 사람에게는 검증을 통과한 후보만 도달하게 한다. 셋째, 메타인지 — 시스템이 자기 판단의 신뢰도를 아는 능력이다. 1단계부터 쌓인 판단 로그를 학습해, 제안 유형별 승인율·수정률·사후 적중률을 산출하고, 성적이 검증된 유형은 사후 보고형 자동 실행으로 승격하며 성적이 흔들리는 유형은 게이트를 다시 세운다(1부 5장의 "자동화의 범위는 이념이 아니라 성적표가 결정한다"의 데이터 구현). 선택적으로, 스키마가 충분히 성숙한 영역에 OWL 추론기(ELK 또는 RL 프로파일)를 도입해 스키마 모순 탐지와 분류 자동화를 야간 배치로 돌린다.

## 6.2 데이터 준비 체크리스트 15항

로드맵의 각 단계가 딛고 설 데이터 기반을 15개 항목으로 점검한다. 각 항목은 "문서가 있는가"가 아니라 "시스템이 참조 가능한 형태로 존재하며 갱신 책임자가 있는가"로 판정한다.

| 번호 | 항목 | 판정 기준 |
|------|------|------|
| 1 | 공통 코드체계 | 품목·거래처·공정·사유 코드가 단일 체계이고 시스템 간 사본이 없다 |
| 2 | 온톨로지 스키마 정의서 | 클래스·관계·속성의 정의와 명명 규칙이 문서·그래프 양쪽에 존재한다 |
| 3 | 온톨로지 공리 목록 | 도메인·레인지·카디널리티·전이성 등 공리가 명시되어 추론·검증에 쓰일 수 있다 |
| 4 | SHACL 제약 목록 | 핵심 엔터티별 필수 속성·값 범위·관계 제약이 셰이프로 선언되어 있다 |
| 5 | 판단 로그 스키마 | 제안·근거·검증 결과·결정·이유·사후 결과가 구조화되어 축적된다 |
| 6 | 규칙 대장 | 비즈니스 규칙의 목록·출처(명문/발굴)·버전·소유자가 단일 저장소에 있다 |
| 7 | KPI·CTQ 정의서 | 각 지표의 계산식과 원천 필드가 정의되고 계보로 추적 가능하다 |
| 8 | 마스터 데이터 품질 지표 | 재고 정확도·BOM 정확도·라우팅 완전성이 측정되고 목표치가 있다 |
| 9 | 데이터 계보 기록 | 원장→그래프→지표의 변환 이력이 자동 수집된다(OpenLineage류) |
| 10 | 시맨틱 카탈로그 엔트리 | 데이터 자산별 정의·동의어·책임자·민감도가 검색 가능하다 |
| 11 | 임베딩 인덱스 관리 | 벡터 인덱스의 원천·생성 모델·재생성 주기가 기록된다 |
| 12 | 모델 버전·평가 기록 | 예측 모델의 버전·학습 데이터 범위·평가 지표(MAPE 등)가 관리된다 |
| 13 | 승인 권한 매트릭스 | 판단 유형별 승인 자격이 조직·직무 기준으로 정의된다(Harness) |
| 14 | 감사 로그 보존 정책 | 판단·승인·변경 로그의 보존 기간·불변성·접근 통제가 정의된다 |
| 15 | 예외·반례 사례집 | 규칙이 틀렸던 사례와 경계 조건이 수집되어 규칙 개정의 입력이 된다 |

열다섯 항목 중 1·2·7·8·13은 책의 1~3부가 이미 세운 것이고, 3·4·5·6·9는 로드맵 1~2단계의 산출물이며, 11·12·14·15는 운영이 성숙하며 채워진다. 15번 항목을 특히 강조해 둔다. 규칙의 가치는 맞은 사례가 아니라 틀린 사례의 관리에서 판가름 난다 — 반례 없는 규칙 대장은 검증되지 않은 신념의 목록일 뿐이다.

## 6.3 리스크와 정직한 평가

이 보강이 공짜가 아니라는 사실을 세 가지 리스크로 명시한다.

첫째, 온톨로지와 규칙의 유지 비용이다. 스키마와 셰이프와 규칙은 세우는 것보다 살아 있게 하는 것이 어렵다. 사업이 바뀌면 클래스가 바뀌고, 클래스가 바뀌면 셰이프와 규칙과 근거 UI가 연쇄로 바뀐다. 이 유지에는 명시적 역할 — 최소한 겸직의 온톨로지 관리자(knowledge steward) — 과 개정 절차가 필요하며, 그 비용을 감당할 수 없는 조직에는 셰이프·규칙의 범위를 핵심 의사결정 몇 개로 좁히는 것이 정직한 처방이다. JEDAIX의 Progressive Ontology가 보여주듯, 작게 시작해 검증된 것만 늘리는 정원의 전략이 대성당의 전략보다 오래 살아남는다.

둘째, 규칙 폭발(rule explosion)이다. 규칙이 수백 개로 늘면 규칙 간 중복·충돌·순환이 새로운 종류의 부채가 된다. 평가 성능 자체는 Rete 계열 알고리즘이 해결해 주지만(Forgy, 1982), 의미적 관리 — 두 규칙이 같은 상황에 다른 결론을 내리는 경우의 탐지 — 는 알고리즘이 해결해 주지 않는다. 완화책은 세 가지다. 규칙 대장의 단일화(6.2의 6번), DMN 의사결정 표처럼 충돌이 눈에 보이는 표현 형식의 선호, 그리고 모든 규칙에 출처(어느 발화·어느 검정에서 왔는가)와 반례(15번)를 붙여 폐기 가능성을 열어 두는 것이다. 규칙은 자산인 동시에 부채이며, 늘리는 절차만 있고 줄이는 절차가 없는 규칙 체계는 반드시 경화된다.

셋째, 성능과 이중화의 비용이다. 완전한 OWL DL 추론은 지수적 복잡도의 세계이므로 실시간 의사결정 경로에 두어서는 안 되며, EL·RL 프로파일 추론이나 야간 배치로 격리해야 한다. SHACL 전수 검증도 그래프가 커지면 배치·증분 검증의 설계가 필요하다. 그리고 속성 그래프 본체에 RDF 표준 계열의 검증·추론을 얹는 절충은 두 표현 사이의 변환 비용과 의미 손실 가능성 — 속성 그래프의 관계 속성이 RDF로 곧장 옮겨지지 않는 임피던스 — 을 수반한다. 이 비용이 과도해지는 지점에서는 표준 순수주의보다 실용주의를 택한다 — 검증의 목적은 표준 준수가 아니라 판단의 안전이며, 사이퍼로 구현된 제약 검사도 셰이프 선언과 판정 기록이 남는다면 충분히 심볼릭 검증이다.

마지막으로 가장 근본적인 한계를 적는다. 검증 계층은 명시된 제약만 검증한다. 우리가 셰이프와 규칙으로 쓰지 못한 위험 — 폴라니의 잔여 — 은 여전히 사람의 감각에만 걸린다. 그러므로 뉴로-심볼릭의 완성은 HITL의 폐지가 아니라, 사람의 주의를 형식 검증이 못 미치는 곳으로 재배치하는 것이다. 기계가 계약을 지키는지 검사하는 동안, 사람은 계약 자체가 옳은지를 본다.

## 핵심 요약

- 보강 로드맵은 3단계다. 1단계(0~6개월)는 판단 로그 표준화와 SHACL 제약의 리포트형 도입·용어집 통합, 2단계(6~12개월)는 규칙 대장·규칙 엔진 이관과 설명 리포트의 제품화·계보 표준화, 3단계(12~24개월)는 범용 솔버 통합·제안-검증 협상 루프·메타인지 기반 자동화 승격이다.
- 검증은 리포트로 시작해 게이트로 승격시킨다. 위반 실태를 모른 채 게이트를 세우면 업무가 멈추고, 게이트 없는 리포트는 읽히지 않는다.
- 성공 판정은 단계별로 명시된다 — 판단 로그 100건과 위반율 하강(1단계), 상신 100%의 규칙 판정표·근거 리포트 동반(2단계), 자동 실행 승격 유형 3개 이상과 검증 우회 0건(3단계).
- 데이터 준비 체크리스트 15항은 코드체계·스키마·공리·셰이프·판단 로그·규칙 대장·계보·카탈로그 등으로 구성되며, 판정 기준은 "시스템이 참조 가능하고 갱신 책임자가 있는가"다. 반례 사례집(15번)이 규칙 체계의 건강도를 결정한다.
- 리스크는 셋이다. 온톨로지·규칙의 유지 비용(정원의 전략으로 완화), 규칙 폭발(단일 대장·DMN 표·폐기 절차로 완화), 추론 성능과 표현 이중화 비용(프로파일 제한·배치 격리·실용주의로 완화).
- 검증 계층은 명시된 제약만 지킨다. 뉴로-심볼릭의 완성은 HITL의 폐지가 아니라 사람의 주의를 형식 검증 너머로 재배치하는 것이다.

# 결론

온톨로지 다음의 세상은 온톨로지를 버리는 세상이 아니라, 온톨로지가 검증자가 되는 세상이다. 지금까지 우리의 온톨로지 지식그래프는 주로 컨텍스트의 공급자였다 — LLM이 참조할 사실의 척추, 역추적의 지도, 유사 사례의 창고. 뉴로-심볼릭이 요구하는 다음 역할은 판정의 주체다. 그래프 위에 선언된 셰이프가 데이터의 계약 위반을 잡아내고, 그래프에서 자란 규칙이 제안의 적법성을 판정하며, 그래프의 공리가 스키마의 모순을 탐지한다. 같은 온톨로지가 읽기 전용의 참고서에서 집행력을 가진 심판으로 승격되는 것 — 이것이 이 보고서가 그린 전환의 전부이며, 그래서 방향을 바꿀 필요가 없다. 8계층 참조 아키텍처에 비추어 우리의 뼈대는 다섯 계층이 서 있고 셋이 부분 시공이었으며, 보강 공사는 새 부지의 매입이 아니라 기존 골조 위의 층 올리기다. DMAIC 루프는 이미 융합 추론의 박자로 돌고 있고, PTGDA는 이미 뉴럴에서 심볼릭으로 지식을 길어 올리고 있으며, HITL은 이미 거버넌스의 관문을 지키고 있다. 더할 것은 검증의 형식화(SHACL·규칙 엔진), 설명의 제품화(근거 UI·계보), 그리고 조합 문제의 정공법(솔버)이다.

책 3부작과의 관계도 이 문장으로 정리된다. 1부가 데이터의 품질과 루프(개선의 방법론)를, 2부가 단일 원장과 부스터(플랫폼의 실장)를, 3부가 암묵지의 발굴과 판단 계층(온톨로지의 성장)을 세웠다면, 이 보고서는 그 세 층이 이미 하나의 뉴로-심볼릭 의사결정 플랫폼의 골격이었음을 사후적으로 증명하고, 남은 시공 목록을 건넨다. 서드브레인 — 1st Brain의 경험과 2nd Brain의 기록 위에서 융합판단을 내리는 세 번째 뇌 — 는 결국 두 반구를 가진 뇌여야 한다. 패턴을 직관하는 뉴럴의 반구와 규칙을 집행하는 심볼릭의 반구, 그리고 그 사이에서 제안과 검증을 오가는 뇌량. 이 보고서의 8계층은 그 뇌의 해부도이고, 로드맵은 그 뇌량을 두껍게 하는 훈련 계획이다. 판단 시스템(System of Intelligence)의 다음 단계는 더 큰 모델이 아니라 더 엄격한 검증과 더 투명한 설명이며, 그 두 가지는 이미 놓인 뼈대 위에서 시작할 수 있다.
