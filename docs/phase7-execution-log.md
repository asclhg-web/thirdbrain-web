## P7-1: 프로젝트·KPI 센터 코어 (2026-09-12 02:2x)

  모듈·알고리즘을 고르고 KPI를 선정 → 대시보드에서 성과를 보고 →
  개선점 피드백 → KPI 조정/데이터 재축적의 무한 개선 루프. 7단계
  실행계획서에 반영.
- **projects.py 신설(M0-P)**: 5대 영역 카탈로그(영역→플랫폼 실물 모듈·
  알고리즘·KPI 후보 — 존재하는 구성요소만 기재), 프로젝트 정의 시 선택
  영역의 KPI 자동 등재(목표는 사람이 설정), 목표 설정·조정은 feedback
  이력으로 보존(루프의 조정 단계).
- **KPI 실측 엔진(정직 구분)**: 사실 테이블에서 계산 가능한 지표
  (WAPE·폐기율·계획준수율·정비 평균 소요·월 고장 건수·승격 규칙 수)만
  측정하고, 불가한 지표(결품 일수·예측 편향·리드타임·질문 활용)는 값을
  지어내지 않고 '측정 전 + 필요한 데이터'를 말한다. 측정치는 이력으로
  쌓여 차트의 원천이 된다.
- 테스트 5건(카탈로그 등재·검증·정직 pending·실측/판정/조정 루프·
  시계열 누적).
- **P7-I1 발견·해소**: 스위트가 116개로 커지자 PG 프로파일별 캐시 연결

## P7-2: 프로젝트 화면 — 정의 위저드 + KPI 대시보드 (2026-09-12 02:3x)

- **/projects**: 목록 + 새 프로젝트 정의 위저드 — 이름·경영 목표·5대

  admin 목표 조정 폼(사유 필수 이력) + 지금 측정 버튼(steward·admin) +
  선택 모듈·알고리즘 표 + 피드백·조정 이력 표(루프의 기록).

## P7-3: KPI 무한 개선 루프 — 에이전트·스케줄러 결선 (2026-09-12 02:4x)

- **kpi_agent(7호 에이전트)**: 활성 프로젝트의 목표 설정 KPI를 최신 실측과
  대조 — 미달이면 개선 제안 판단 카드(현재값·목표·근거 출처·우선 점검
  지렛대=그 영역의 선택 모듈)를 승인함으로. 같은 KPI의 대기 카드가 있으면
  중복 생성하지 않는다. 목표 미설정 KPI는 제안하지 않는다(사람의 결정 선행).
- **환류**: kpi_improve 카드 승인 시 improve 피드백이 이력에 기록되고,
  다음 야간 측정이 재판정 — 여전히 미달이면 새 카드, 달성이면 침묵.
- **스케줄러**: projects_measure 단계(에이전트 실행 전 자동 측정) 추가 —
  측정→제안→승인→기록→재측정의 루프가 야간 배치에 상시 결선됨.
- **E2E 실증(테스트)**: 준수율 70%·목표 90% → 카드 1건(근거 문구 포함) →
  중복 방지 → 승인 → 피드백 기록 → 실적 95% 후 재측정 '달성' → 카드 0건.
- 스키마 교정: 측정 테이블에 m_id(동일 초 다중 측정 순서 보장) — 측정치는
  재계산 가능한 파생값이라 구버전 테이블은 재생성(원장 아님, 손실 무해).
- 테스트 117+5skip(SQLite)/122(PG) 전부 통과.
