## 환경 제약에 따른 설계 결정 (착수 시점)

- [D-01][전역] **Docker 데몬 없음** — 이 빌드 환경에서는 컨테이너를 띄울 수 없다.
  결정: 코어를 저장소-추상화(SQLite demo ↔ PostgreSQL prod)로 설계하고,
  deploy/docker-compose.yml은 현장 배치용으로 작성만 한다(기동 검증은 현장 몫).
  후속: 현장 서버에서 runbook.md대로 기동 검증 필요.
- [D-02][M4] **TensorFlow·RLlib 미설치** — 용량·GPU 제약.
  결정: 계획서의 "단순한 것부터" 규율대로 평활→GBDT(scikit-learn)를 기본 구현,
  딥러닝은 선택적 임포트 훅(백엔드 교체 지점)으로 남긴다. RL은 재고 Twin 안의
  정책 탐색(교차 엔트로피 방식)으로 구현 — 계획서의 안전장치(시뮬레이터 밖 학습 금지,
  산출은 카드로만)는 동일하게 강제된다.
  후속: GPU 서버 확보 시 M4-2의 TF 시계열, M4-4의 RLlib 백엔드 교체 검토.
- [D-03][M4] **MLflow 대신 경량 모델 카드 레지스트리** — 데모 모드에서 서비스 의존을
  없애기 위해 카드 레지스트리를 파일+DB로 자체 구현(필수 항목 강제 동일).
  prod compose에는 MLflow 서비스 포함 — 어댑터로 연결하는 구조.
- [D-04][M5] **Neo4j demo 대체** — demo 모드는 SQLite 트리플 저장소+networkx로 동작,
  Cypher 내보내기(neo4j_export)로 prod 이관. 스키마·확신도 로직은 동일.
- [D-05][M6] **LLM demo 대체** — Ollama 없는 환경이므로 demo 모드는 결정적
  문장 조립기(템플릿+그래프 근거)로 동작. "창작이 아니라 조립"이라는 M6 원칙과
  일치하며, Ollama 백엔드는 어댑터(judge/assembler.py의 LLMBackend)로 접속.
- [D-06][M1] **실제 Odoo 없음** — demo 모드는 합성 Odoo 스키마(sqlite)를 원천으로
  CDC를 폴링 방식으로 재현. prod용 논리 복제 구성은 문서·SQL로 제공.

- [D-07][M4] **오토인코더 → PCA 재구성 오차** — TF 미설치 환경에서 같은 원리
  (정상 압축·복원 오차)로 구현. 인터페이스(fit/score) 동일 — TF/Keras AE로
  교체 가능한 훅 유지. 데모 데이터에서 recall 1.0·선행 13일로 충분.

## 구축 중 발견·수정한 이슈

- [I-01][M4-3] **이상탐지 1차 학습 실패(recall 0)** — 정상 구간에 고장 전
  드리프트 2주가 섞여 '이상을 정상으로' 학습. 원인 둘: ① 센서 이력 90일로
  정상 표본 부족 ② 학습 창 정의가 정비 이력과 무관.
  수정: 센서 180일로 확대, 학습 창을 고장·정비일 제외 규칙으로 강제.
  교훈: **정상 구간의 정의가 모델보다 중요하다** — 실 배치 시 정비 이력 연동 필수.
- [I-02][M4-4] **Twin 재생 검증 1차 실패(폐기율 9.5배)** — 재생용 예측을
  지수평활로 넣어 주말 피크를 놓침 → 현장 발주 관행(지난주 같은 요일)과 불일치.
  수정: 재생 검증은 dow 예측 기준으로. 교훈: 재생 검증의 기준은 '좋은 모델'이
  아니라 '현행 관행'이다.
- [I-03][M6-1] **인용 검증기 백분율 오탐** — 그래프의 0.875를 문장에서 88%로
  표기하자 '창작 수치'로 차단. 수정: 검색 수치의 ×100 표기 허용 목록 추가.
  교훈: 환각 차단기는 표기 변환 규칙을 명시적으로 가져야 한다.
- [I-04][M4-2] **분류기 임계 탐색이 패자 모델 확률 사용** — 로지스틱이 이겼는데
  GBDT 확률로 임계를 정함 + 원핫 컬럼명 파싱 오류("product_id_P-X"를
  "product"로 분해). 둘 다 수정, M5 후보 변환이 vendor=V2를 정확히 전달.
- [I-05][M3-1] **matplotlib 3.9+ API 변경** — boxplot(labels=) 제거됨 →
  tick_labels로 수정.
- [I-06][E2E] **numpy bool JSON 직렬화 실패** — 요약 저장 시 default 핸들러 추가.
- [I-07][M6 회귀] **고정 RULE-ID 의존** — 회귀 10선이 RULE-0001을 하드코딩,
  새 DB에서 승격 순서가 달라지자 실패. 첫 승격 규칙 동적 조회로 수정.
  교훈: 회귀 시험은 값이 아니라 관계를 고정해야 한다.
- [I-08][환경] **작업 중 컨테이너 재생성** — 세션 환경이 초기화되어 노드 모듈·
  아파트 패키지·산출물 소실. 저장소 커밋분으로 전부 복원(문서 내 그림은 DOCX
  에서 재추출). 교훈: "커밋되지 않은 것은 자산이 아니다"가 이 세션에서도 성립.

- [I-09][M2] **잘못된 스튜어드 확정이 하류를 오염** — E2E 시연 코드가 격리 큐
  첫 건을 무조건 'P-PIE'로 확정 → 코드 사전 오염 → 엑셀 검증에서 P-PIE 수량이
  원장의 1.6배로 불일치 15건. 새로 만든 교차 원천 검증(validation.excel_vs_ledger)이
  즉시 잡아냈고, 확정 로직을 수정해 0건으로 회복.
  교훈: **격리 확정은 되돌릴 수 있어야 하고, 교차 검증이 확정의 감사자다** —
  스튜어드 확정 실수는 반드시 일어난다. 검증 잡을 야간 배치에 편입.
