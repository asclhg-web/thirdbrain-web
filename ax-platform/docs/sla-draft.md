# AX 플랫폼 서비스 수준 협약(SLA) 초안 — 파일럿용 v0.1

> 파일럿 계약의 부속 문서 초안. 수치는 이 저장소에서 **실측된 값**을 근거로
> 잡았고, 현장 인프라 실측 후 본계약에서 확정한다. (P3-6)

## 1. 적용 범위와 전제

- 대상: AX 플랫폼 파일럿(단일 고객사, 앱 서버 1대 + GPU 서버 1대 구성).
- 전제: 서버 사양·네트워크는 진단 제안서 2장의 최소 사양 충족,
  Odoo 원장 DB는 wal_level=logical 설정 가능, 정전/회선 장애는 불가항력.
- 이 SLA는 파일럿 기간(12주) 한정이며, 정식 운영 SLA는 파일럿 실측으로 갱신.

## 2. 서비스 수준 목표(SLO)

| 항목 | 목표 | 실측 근거(이 저장소) |
|---|---|---|
| 웹앱 가용성(영업시간 07~22시) | 99.0% (월 기준) | 3일 소크 무중단, 부하 820요청 무오류 |
| 웹앱 응답(p95, 동시 20명) | ≤ 1초 | 실측 p95 319ms — 여유 3배 |
| 질문(그래프 근거 질의) 응답 p95 | ≤ 3초 | 실측 p95 93ms(결정적 조립기 기준) |
| 야간 파이프라인 완료 | 익일 06:00 이전 | E2E 전 구간 53.5초(PG) — 여유 충분 |
| CDC 복제 지연 | ≤ 5분 (경보 임계) | 슬롯 lag 모니터링 단계 내장 |
| 판단 카드 생성 → 승인함 노출 | 야간 배치 후 즉시 | 스케줄러 17~20단계 검증 |
| 백업 | 일 1회 전체 + WAL, RPO ≤ 24h / RTO ≤ 1h | P2 복구 리허설 실측 RTO 수 분 |
| LLM 서술(GPU 서버) 불통 시 | 결정적 조립기 자동 폴백(기능 저하 없음) | OllamaBackend 폴백 테스트 |

주의: 가용성·지연 목표는 **플랫폼 구간**에 한한다. Odoo 원장 자체의 장애,
고객사 내부망 장애는 측정에서 제외하되 복구 협조는 3장 대응 시간에 따른다.

## 3. 장애 등급과 대응 시간

| 등급 | 정의 | 응답 | 복구 목표 |
|---|---|---|---|
| P1 | 승인함·환류 전면 불가(발주 초안 생성 불가 포함) | 30분 내 | 4시간 |
| P2 | 야간 파이프라인 실패(브리핑/카드 미생성), CDC 지연 > 1h | 2시간 내 | 당일 |
| P3 | 일부 화면·보고서 오류, 특정 카드 오류 | 당일 | 3영업일 |
| P4 | 개선 요청·질의 | 익영업일 | 협의 |

- 연락 창구: 담당 엔지니어 직통(파일럿 기간) + 장애 알림 채널(텔레그램/웹훅 —
  notify 모듈 내장). P1/P2는 플랫폼이 먼저 감지·경보하는 것을 원칙으로 한다
  (crit 경보 → 채널 발송, 3일 소크에서 자기 감지 실증).

## 4. 정기 점검·보고

- 주간: 지식 퍼널 리포트(승격/강등/FP율 — War Room 내장 지표) + 파이프라인 성공률.
- 월간: SLO 달성률 보고서, 모델 재학습 결과(WAPE 추이), 백업 복구 리허설 1회.
- 분기: 회귀 30선 전체 재실행 결과, 보안 점검(계정·권한·PII 차단 로그).

## 5. 책임 한계(정직 조항)

- 판단 카드는 **제안**이다. 발주·생산 확정은 언제나 사람의 승인을 거치며,
  승인된 제안의 사업 결과(과잉/과소 발주 등)는 SLA 배상 대상이 아니다.
- 예측 정확도(WAPE 등)는 SLO가 아니라 **월간 보고 지표**다 — 정확도는 데이터
  품질에 종속되며, 저하 시 원인 분석과 개선 계획을 보고할 의무만 진다.
- 합성/샘플 데이터로 시연된 성능은 참고치이며, 실데이터 온보딩 후 4주차에
  기준선을 다시 잡는다.

## 6. 배상(파일럿)

파일럿 기간 월 이용료의 환급 상한: 가용성 99.0% 미달 시 10%,
97.0% 미달 시 30%. 그 외 배상은 없다(파일럿 요율에 반영).
