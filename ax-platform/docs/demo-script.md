# 10분 시연 대본 — "판단의 공장이 돈다"

대상: 경영진·예비 고객사. 목표: 기능 나열이 아니라 **판단 한 장이 태어나서
원장을 바꾸기까지**를 한 호흡으로 보여준다.
사전 준비: `python -m demo.run_e2e` 완료 상태 + `uvicorn axp.api:app --app-dir core --port 8000` 기동.

## 0. 오프닝 (30초)

> "이 회사는 가상의 제빵회사입니다. 24개월치 판매·생산·품질 데이터 속에
> 저희가 **일부러 불량 원인 하나를 심어 뒀습니다**. 지금부터 10분 동안,
> 플랫폼이 그 원인을 스스로 찾아 지식으로 만들고, 내일의 발주·생산을
> 바꾸는 것까지 보시겠습니다. 사람이 하는 일은 단 하나 — 승인입니다."

## 1. 아침 브리핑 (1분) — `artifacts/briefings/`

- 보여줄 것: "어제의 변화 Top 5" — 전부가 아니라 **변화만**, 원인 단정 없이
  '함께 나타났다'까지만. 급증 키워드("반죽·되직함·오븐2") = 현장의 말.
- 멘트: "아침 회의가 이 한 장으로 5분에 끝납니다. 모든 수치에 출처가 붙습니다."

## 2. 층별·관리도 (1분 30초) — `artifacts/eda/`

- stratify_equipment.png → "OVEN-2가 눈에 띕니다."
  pchart_all.png → "7~8월에 관리 이탈 점들 — 언제부터인지가 보입니다."
- 멘트: "여기까지는 좋은 분석 도구면 다 합니다. 지금부터가 다릅니다."

## 3. 원인 후보 → 규칙 승격 (2분) — CLI 또는 /rules

```bash
PYTHONPATH=core python -m axp.cli ask "OVEN-2 원인" --entity OVEN-2
```
- 보여줄 것: "설비 OVEN-2 × 공급사 V2 조합 — 확신도 88%" **모든 문장 끝의
  [근거: …] 태그**. 이어서 역추적 화면(`/rules/RULE-0001/why`):
  규칙→조합→사실 2,254건→원장 레코드 #까지 4층 사다리.
- 멘트: "야간 마이닝이 3주에 걸쳐 3번 독립 확인했고, 임계(70%·3회)를 넘자
  **사람에게 상신**했습니다. 승인해야 규칙이 됩니다 — 여기 승인 이력이 있습니다.
  그리고 이 규칙은 SOP 개정 제안으로 이어졌습니다. 지식이 절차가 되는 순간입니다."

## 4. 승인함 (3분) — `/inbox` ★ 하이라이트

- 대기 카드 훑기: 수요예측(구간 병기), **생산계획(용량 경고)**, 보충 정책(Twin
  절감률), 배분, 설비 계획 정비(연속 경보).
- 시연: 카드 하나 '왜?' 클릭 → 근거 전개. **역할을 '스튜어드'로 바꿔 승인 시도
  → 403 거부** ("권한은 구조가 지킵니다"). 역할 복원 → 승인 →
  "환류 완료: forecast_qty… " 메시지.
- 멘트: "승인 순간에만 원장이 바뀝니다. 누가·언제·무엇을·이전 값이 무엇이었는지
  전부 감사 로그에 남았습니다. 반려하면 그 사유가 다음 학습의 재료가 됩니다."

## 5. War Room (1분 30초) — `/warroom?as_of=…`

- 상단 KPI → 반려 사유 분포 → 에이전트 오류 0 → 드리프트 → **리스크 5 신호등**.
- 멘트: "주간 회의는 이 화면 순서대로 15분입니다. 자동 실행도 보이시죠 —
  상한 이내 저위험 카드만, 승급 절차를 통과해야, 그리고 승인율이 떨어지면
  스스로 강등됩니다."

## 6. 클로징 (30초)

> "오늘 보신 규율 — 계약 없는 연결 금지, 근거 없는 문장 금지, 승인 없는 변경
> 금지 — 는 문서가 아니라 코드가 강제합니다. 이 데모는 합성 데이터지만,
> 온보딩 준비서의 빈칸을 채우면 귀사의 데이터로 12주 안에 같은 화면이 돕니다.
> 첫 유스케이스는 수요예측 — 얇게, 끝까지, 12주입니다."
