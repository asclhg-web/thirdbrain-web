# 성능 실측 노트 (demo 모드, 단일 노드 SQLite)

측정 환경: 데모 데이터 24개월(판매 21,900행 · 생산 10,426 · 품질 9,839 ·
센서 156,384), 컨테이너 vCPU 공유 환경. 절대값보다 **비례 관계**를 보라.

## 단계별 실측

| 단계 | 규모 | 시간 | 비고 |
|---|---|---|---|
| CDC 정합 배치 | 6계열 전체 대조 | 0.04s | 집계 쿼리만 |
| 표준 변환 전체 재구축 | 사실 65,606행 | 1.7s | 멱등 전량 재구축 방식 |
| 품질 게이트+리포트 | 규칙 34건 | 0.2s | 계약에서 자동 생성 |
| 특징 생성(21k 행) | 30 계열 × 730일 | 3.4s | point-in-time 롤링 |
| 특징 생성(**2배** 42k 행) | 60 계열 | 6.0s | **선형 스케일 확인(×1.75)** |
| 야간 마이닝(56일 창) | 4M 조합 탐색 | 0.06s | |
| 그래프 백필 전체 | 이벤트 9,839 × 간선 5만 | 7.4s | 야간 증분은 <0.1s |
| 예측 학습+롤링 4폴드 | GBDT 3모델(P10/50/90) | 7.2s | 주 1회만 |
| E2E 수직 완주 전체 | 0→판단 환류 | ~80s | 일 배치 실사용은 이 중 일부 |

## 스케일 전망

- 야간 배치의 지배 항목은 특징 생성·학습 — 둘 다 데이터량에 **선형~n log n**.
  매장 40곳·품목 100종(격자 ~50만 행/일 아님, 계열 4,000개 × 730일)이면
  특징 생성 수 분대 — 야간 창(6시간) 대비 여유 큼.
- SQLite demo의 한계는 동시성(단일 쓰기) — prod는 PostgreSQL로 그 제약이 없다.
  코어 로직은 동일하므로 이 실측의 비례 관계는 유지된다.
- 센서는 일 집계(fact_sensor_daily)로 흡수 — 원시 156k행이 348행이 된다.
  설비 100대×10신호여도 일 1,000행 수준.
- 전량 재구축 변환은 사실 1천만 행 근처에서 증분 전환 필요(설계상 소스
  워터마크만 추가하면 됨) — 1단계 고객사 규모에서는 불필요.
